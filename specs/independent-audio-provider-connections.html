ASR・TTS の接続と利用を LLM から独立させる

2026-10-25 の修正仕様。音声 Provider の起動・確保・readiness・claim・推論・認証情報の更新は、その Provider 自身の状態だけを条件にする。LLM の KV 保持、Allocation 枠、生成、起動、semantic probe、占有保護、Profile 切替の完了を条件にしない。本番反映は2026-10-25に承認され、配備準備中であり、以下はローカル実装の契約である。

確保と起動

Profile の音声 Provider（openai.audio-transcriptions.v1 と openai.audio-speech.v1）を個別の内部 Connection と Allocation に分ける。Provider 名やモデル名には分岐しない。LLM を含む非音声部分は既存の Allocation を継続し、KV 保持のための LLM 接続枠を減らさない。ASR/TTS の確保に LLM の枠を使用しない。

音声の準備処理と容量待ちからの昇格を独立した実行経路で処理する。LLM の読込みが既存 Control の処理列を占めていても音声の起動は開始できる。同一音声 runtime の同時起動は既存 Provider instance 管理でまとめ、メモリ見積り・live telemetry・音声自身の容量・queue・quarantine の制限は維持する。物理資源不足を成功として扱う変更ではない。

音声接続は LLM の usage handover や retain-until-next-profile の置換を起こさず、音声要求は LLM の foreground 排他による背景処理の取消を起こさない。音声要求は LLM 保護期間の activeRequests にも数えない。通常の認証と Provider token の能力・モデル・audience・principal・instance 世代の検証は維持する。

POST と GET の互換性

POST /v1/agent-connections と GET /v1/agent-connections/{id} の応答項目・status と readiness の列挙値は変えない。各 Provider の readiness と claimable を自身の内部 Connection から返す。LLM が waiting のままでも ASR/TTS を ready、claimable=true として返す。接続全体の status=ready は全要求 Provider が準備できたという従来の意味を維持する。 

{"status":"probing","providers":[{"name":"asr","readiness":"ready","claimable":true},{"name":"llm","readiness":"waiting","claimable":false},{"name":"tts","readiness":"ready","claimable":true}]}

この例は該当項目のみの抜粋。全体が probing でも ASR/TTS は利用可能である。LLM が失敗して全体が failed になった場合でも、独立した音声 Provider が ready なら、その Provider のみの claim と利用は自身の期限まで可能である。POST は一部 Provider の接続を受理できた場合、202 と接続情報を返す。全体の ready を偽装しない。

Provider を指定した claim

既存 POST /v1/agent-connections/{id}/claim に任意の providers を追加する。省略時は従来どおり全 Provider を取得する。指定時は、その Provider だけの状態と semantic readiness を検証して、既存と同じ応答形で descriptor と認証情報を返す。他の Provider の probe を待たず、他の Provider の失敗によって拒否しない。 

{"format":"openai-provider-v1","providers":["asr"]}
{"format":"openai-provider-v1","providers":["tts"]}

claim 応答の status=ready は、返した Provider 集合の準備完了を表す。元の Connection 全体が ready になったという意味ではない。health URL は引き続き公開 Connection ID と Provider 名を指し、音声だけを検証する。認証情報は音声自身の Allocation と instance 世代に結び付ける。親の allocationId を header に指定する既存 consumer も受け入れるが、実転送は token が示す音声自身の Allocation で行う。無関係の Allocation header は拒否する。

同じ client と構成の新しい POST は各 Provider の内部接続・Allocation・有効な認証情報を再利用する。明示 renew は独立した音声の認証情報も更新する。明示 DELETE はその公開 Connection が所有する音声接続も終了させる。LLM の probe 期限切れや LLM 側の idle release を理由に、音声接続を取り消さない。音声自身の期限・無操作解放は引き続き適用する。

Eumenes の呼出し

音声開始時には GET の providers 内で asr の readiness=ready を待ち、providers=["asr"] で claim して文字起こしを開始する。発話時には tts の readiness=ready を待ち、providers=["tts"] で claim する。LLM は自身の ready を待って別に claim する。全体の status=ready と全 Provider の ready を待ってから ASR を始める consumer 側の手順は、引き続き LLM を待つため変更が必要である。本修正では Eumenes のコード・設定・配備は変更していない。

既存 API だけでも providers=["asr"]、providers=["tts"] をそれぞれ指定して別 Connection を作成でき、これらも LLM の占有・切替を待たない。SDK には既存 waitForAgentConnection の providers オプションと claimAgentConnection の Provider 指定を追加した。 

const audio = await client.waitForAgentConnection(connection, { providers: ["asr"] });
const claim = await client.claimAgentConnection(audio.id, {
  format: "openai-provider-v1", providers: ["asr"]
});
