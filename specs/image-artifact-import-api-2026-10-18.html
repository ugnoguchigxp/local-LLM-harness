画像専用の取込APIとEumenes連携

2026-10-18。端末やGoogleフォトからEumenesが取得した画像bytesをControlへ送信し、既存の画像一覧・取得・削除と3D入力に使う。汎用ファイル保管やGoogle認証は追加しない。画像生成・3D生成・GPU起動を伴わないCPU処理。

正式契約

エンドポイント
操作 契約
POST /v1/image-artifacts/imports Control Bearer、UUIDのIdempotency-Key必須。multipart/form-dataのfileを1個のみ。ほかの項目、URL、ホストパスは拒否。
GET /v1/image-imports/{requestId} アップロード時と同じControl Bearerで照会。requestIdは送信前に永続化したIdempotency-KeyのUUIDそのもの。大文字は小文字に正規化。
既存の画像API 一覧、個別GET、content GET、DELETEに同じimage_ + 32桁hexのIDが現れる。3D生成のsourceにはtype=image-artifactとそのidを指定。

入力はJPEG/PNG/WebPの静止画、最大16 MiB（16,777,216 bytes）、幅・高さとも最大2000px、最大4,000,000画素。2000×2000を許可、2001pxの辺は拒否。LARMは暗黙の縮小をしない。multipart全体は16 MiB + 64 KiBまで。保存後は20 MiBまで。

Eumenesは既存画像変換を共通化し、原本にEXIF向き補正、縦横比維持・拡大なしの長辺2000px以内の縮小、非可逆WebP quality 75、透過維持、メタデータ除去を行って送る。品質75はEumenesの送信条件であり、LARMが再圧縮したり品質を推定したりしない。

WebPはPillowで実体を完全decode検証し、VP8/VP8L/ALPH圧縮payloadを保持して保存する。EXIF/ICC/XMP等のコンテナメタデータは除去し、VP8Xの対応フラグも除去する。メタデータがない通常WebPは同じbytesになる。WebPの非標準向き（EXIF orientationが1以外）は415 webp_orientation_unsupportedとし、送信前に補正する。JPEG/PNGはEXIF向きを補正し、新しいRGB/RGBA画素からメタデータなしPNGへ保存する。透過は保持。HEIC、SVG、動画、アニメーション、破損、偽MIMEは対象外。

成功画像のartifactはid、createdAt、format、mimeType、width、height、hasAlpha、bytes、sha256、contentUrl。sha256は保存後bytesの値。model、seed、stepsは付与しない。元ファイル名、原本bytes、資格情報は保存・記録しない。元の端末画像やGoogle写真は変更しない。

成功・失敗・成否不明時

全receiptはrequestId、createdAt、expiresAt、statusUrlを持つ。statusはpending / succeeded / failed。succeededかつdeleted=falseにはartifact、明示削除・保存保持処理で画像が失われた後はdeleted=trueとartifactIdのみ。failedにはerror.codeとerror.message。

POSTの初回完了は201、完了済み再送は200、処理中は202。LocationはstatusUrl、202にはRetry-After: 1。短時間で終わらない処理は接続とは独立して完了する。GETはpending / succeeded / failedをHTTP 200で返す。最初のPOSTでも失敗が確定すれば該当HTTPコードでfailed receiptを返す。受付前の拒否は通常のerrorのみでreceiptを作らない。

同一Control Bearer主体・同一UUID・同一元file bytesなら同じreceipt。同じキーで異なる元bytesは409 idempotency_conflict。multipart境界やファイル名は同一性に含めない。異なるBearerのreceiptは見えない。Bearer変更後に過去キーを自動再送しない。画像自体の既存共有Controlライブラリの公開範囲は維持する。

応答断では既知のUUIDでGETする。pendingなら待つ、succeededなら返されたIDを使う、failedなら失敗表示。404なら受付前の可能性があるため同じUUID・同じbytesで再送する。受付済み失敗を同じキーで再実行しない。明示的にやり直す場合だけ、新しいUUIDを使う。

receiptの照会期限は受付から7日。期限後はGET・同じbytesのPOSTとも410 image_import_receipt_expired。二重保存防止のキーと元bytesのdigestは保持し、期限切れキーを再利用しない。削除済み画像も同じキーでは再作成しない。

保存と再起動

既存画像rootのYYYY/MM/image_IDへ保存。同じドライブと既存の容量・削除管理を使う。取込は容量不足のため他画像を削除しない。既存生成側の画像pool保持方針は継続する。importはpool上限とディスク空き64 MiBの余裕を検証して不足を507で返す。

root/.imports/receiptsは画像本文なしの永続receipt、root/.imports/workは処理中だけの非公開bytes。既存3D journalと同じ一時ファイル・fsync・rename・親ディレクトリfsync方式。receipt intent→検証済み画像とmetadataの原子的rename→succeededの順で保存。daemonは1 writerを前提とする。

再起動時のpendingは再実行しない。すでに公開済みでhash一致ならsucceededへ復元、公開前ならfailed / image_import_interrupted。削除intentは本体削除前に保存し、中断した削除は起動時に完了。receiptが読めなければ取込を停止し、私有workを消さず、既存画像閲覧は維持する。

decodeは既存Qwen環境のPillow 12.2.0をCPUで利用。LARM_IMAGE_IMPORT_PYTHONで実行Pythonを指定可能。1処理にCPU20秒・wall30秒・アドレス空間512 MiBの上限を設け、stderrを記録しない。GPU・MediaVariant・Agent Connectionを取得しない。

検証

JPEG回転、透過PNG/WebP、WebP圧縮payload一致、メタデータ除去、2000×2000許可と両辺2001px拒否、偽MIME・破損・アニメーション・過大入力拒否、並行再送、応答断後照会、再起動境界、削除intent、容量不足時の既存画像保持、画像IDから既存3Dへの入力を自動試験済み。

公開契約はGET /openapi.json。multipart項目、UUIDヘッダー、状態schema、認証、HTTPコードを含む。SDKはclient.images.import / receipt / list / get / content / deleteを提供する。

3Dへの接続

返されたartifact.idを3D要求のsource.type=image-artifact、source.idへ指定する。モデル名は通常catalogのmedia.mesh.generate / larm.mesh-generation.v1から取得する。取込自体にmodelやAgent Connectionは不要。

保存画像・3Dの固定元画像はWebP bytesを維持する。ネイティブ3Dエンジンへの入力時のみ、非公開作業領域に復号画素と同一のPNGを作る。追加の非可逆圧縮は行わず、作業用PNGは成功・失敗後の既存清掃対象に含まれ、画像ライブラリや完成モデルの保存には追加しない。

取込は各辺1〜2000px。既存3D workerの画像制約は各辺32〜4096px・20 MiBであり、3D化に使う画像は各辺32px以上を満たすこと。極小画像は保存・取得できるが3D生成には使わない。

3D生成の現在の要求・応答schemaは本番のGET /openapi.jsonを参照する。
