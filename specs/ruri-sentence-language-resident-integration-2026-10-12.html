Ruri文章言語判定の常駐組込み

2026-10-16に文章日英判定Providerを廃止した。日英判定は呼び出し側の正規表現で行う。現行の判断は廃止決定を参照する。以下は2026-10-12時点の実験・配備記録であり、現行の利用手順ではない。2026-10-16の追加指示により、学習・評価データ、実験コードと外部実測記録は削除済み。配備済み言語headのみ稼働反映まで保持する。

2026-10-12。日本語200文・英語200文を全件学習した二分類ヘッドを、既存の常駐Ruriへ追加する。約342msは試作のencoder・tokenizer初期化を含む時間であり、常駐後の各判定で初期化を繰り返さない。

一つのencoderを共有する二つのタスク

ruri-system-one.service、CPU ONNX Runtime session一つ、tokenizer、lockを共有する。態度の入力tagと6分類ヘッドは維持し、言語判定では学習時どおり「トピック: 」＋原文と別の二分類ヘッドを使う。旧態度の5入力（長文の512-token切詰めを含む）は変更前とanswers・usage・切詰め結果が完全一致した。

両routeはruri-system-oneへ解決し、従来のwarm minInstances 1を使う。新たなencoderプロセスや重みコピーは作らず、head.jsonだけを/srv/ai/models/ruri-sentence-language-v1へhash検証して配置した。capabilityは別にして、同じAgent Connectionで両タスクを要求できるようにした。

healthは旧態度のmodel・labelsを維持し、models配列、encoder_session_count 1、sentence_languageのhead版・追加load時間を加える。既存態度と新しい言語判定の校正・入力形式を混同しない。

Eumenesからの接続

GET /v3/agent-profiles?profile=SAAA-gemma4-26bで発見し、POST /v1/agent-connectionsでprovidersにsentence-languageを指定する。態度も使う場合はsystem-oneを追加する。ready後にclaimされたsentence-languageのendpointとBearer credentialを使う。サービスportを固定のProvider identityとして扱わない。 

{
  "model": "ruri-v3-30m-sentence-language",
  "state": "これは日本語の文章です。",
  "questions": {
    "language": {
      "type": "choice",
      "instructions": "文章全体が日本語か英語かを判定してください",
      "criteria": { "ja": "日本語文章", "en": "英語文章" }
    }
  }
}

POST /v1/systemoneの既存choice契約を使用し、answers.language.choiceがja／enになる。stateは自然文、または既存利用者向けのcurrent_chunk／response object。会話全体を分類せず、current_chunkを優先する。score・noul、候補欠落、別タスクの候補は422。言語判定は512 tokens超を切り捨てず422。claimに違うモデルを指定した場合はgatewayで400、解放後のcredentialは401。

renew後はclaimも更新する。release後は結果を採用しない。今回のモデルは文章全体の二択だけであり、言語区間・境界・休止は返さない。ローマ字は当面対象外。学習400文、追加50文のデータと試験はbenchmarks/sentence-languageに置く。
