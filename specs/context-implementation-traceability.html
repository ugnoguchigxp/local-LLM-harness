M0–M2とCRC32C snapshotのM3b／M4実装は完了し、Qwen 3.8 qualityのlive conformanceでtechnical Goを得た。raw snapshotのM3a No-GoはCRC32C envelope、strict identity、atomic commit、 quarantine、source-rebuild fallbackで閉じた。M5 background最適化は初期経路へ接続しない。 Personal State製品contractについてVC-R06、VC-R08、VC-R10を再監査し、LARM repository実装はPass、 SAAA組込みとlocal-node live受入までは製品gateをNo-Goとする。

再監査で閉じた実装差分

  • Source Providerがcanonical tokenizerのdigestと実token数をsidecar attestationへ固定し、登録APIの 自己申告値だけでは20M admissionを通過できないようにした。
  • generation直前に認定runtimeのchat templateを適用して全promptを再tokenizeし、呼出側が baseInputTokensを過少申告しても225,280 token上限を迂回できないようにした。
  • live runtimeのengine build、chat template、tokenizer behavior、context limitを周期probeし、認定releaseと 一致したHOT／BUSY runtimeだけをACTIVE／BUSYにするようにした。
  • Context mutationのpath-scoped idempotency、100件既定・500件上限のcursor pagination、 materialization operation照会を実装した。
  • source byte quota、filesystem free floor、process間provision lock、optional source drift、deadline、cancel、 metadata commit rollback、bounded operation retentionを実装した。
  • activation、operation、materialization時間、prefill token、cache miss、bypass、cache byteのmetricを追加した。
  • 64 MiB chunk CRC32C、native self-test、atomic commit、lazy verification、破損隔離、512 GiB quota、90%／80% GC、256 GiB free floor、応答完了後saveを実装した。

Personal State追加再監査

DELETE /v1/contexts/:idは既存consumer向けの登録解除であり、依存snapshotとRAM stateは失効するが、source本文、attestation、監査payload、実行中generationの停止完了までを保証する APIではない。Personal StateはPOST /v1/context-forget-operationsを使用し、subject data epochとdurable tombstoneを先にcommitしてから各層のabsenceを照合する。

  • snapshot manifest v2はrequest、View、attempt、source digest、data epochを依存として保持する。
  • forgetとterminal snapshot saveは同じmutation fenceで直列化し、旧epochのcommitを拒否する。
  • 停止不明runtimeはexecution gateで隔離し、slot eraseを確認した再取消／forgetだけが解除する。
  • source、attestation、registry、View、snapshot、RAM slot、auditは別phaseとしてabsenceを返す。
  • 仕様、SAAA側の必須実装、live受入は 改善実装計画と 製品接続handoffを正本とする。
