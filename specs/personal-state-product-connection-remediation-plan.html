Personal State製品接続・忘却保証 改善実装計画

SAAAのPersonal Stateをlocal-LLM-harness（LARM）のManaged Contextへ接続する前に、原文配送、 canonical計測、認証主体、忘却、snapshot、推論取消の契約差分を閉じるための実装計画です。 LARM内部に存在するsource store、Context View、session snapshot、HTTP取消伝播を再利用しますが、 内部機能の存在を製品接続完了とは扱いません。

目的と非目標

目的

  • 応答紛失、consumer再起動、LARM再起動を通常の回復可能状態として扱う。
  • 認証主体、Allocation、runtime、release、tokenizer、chat template、lease epochを一つの証跡へ結ぶ。
  • forgetを単一DELETEの成否ではなく、依存data全体に対するdurable operationとして扱う。
  • 取消後の遅延結果をSAAAで拒否し、LARMでは遠隔計算の停止状態を可能な範囲で証明する。
  • 全失敗経路をfail closedにし、実ユーザーsourceを孤立させない。

非目標

  • 物理媒体上のsecure erase、同一host管理者からの機密保護、暗号学的snapshot完全性。
  • LARMによるPersonal Stateの意味選択、relevance判定、Knowledge生成。
  • モデルweight、inference engine、生成mediaをrepositoryへ格納すること。
  • 通常ProviderへPersonal Stateを暗黙注入すること。
  • 停止確認不能なbackendについて、transport切断だけを遠隔停止完了とみなすこと。

着手時に固定する設計判断

  1. Personal State製品接続は既定無効の独立gateにします。Managed Context全体のkill switchをOFFにしても、 forget、operation照会、absence照会は利用可能にします。
  2. callerが送るowner IDや検証済みbooleanをprincipalの根拠にしません。LARMが発行し署名した安定subjectを Agent Connection、Allocation、Context、source、attemptへ伝播します。
  3. sourceはimmutableにします。同じsubjectとincarnationに同じdigestを再送した場合だけreplayとし、 異なるdigestはHTTP 409相当の固定errorで拒否します。
  4. consumer申告のbaseInputTokensだけで製品Viewを作りません。LARM発行のmeasurement receiptを要求し、generation時のrequest digestと再照合します。
  5. forgetはtombstoneを最初にcommitします。削除処理が途中で失敗しても、対象sourceを新しいView、 generation、snapshot、audit recordへ使用できません。
  6. 登録解除、source unlink、snapshot失効、RAM state解放、audit消去、generation停止は別phaseとして 保存し、すべての必要phaseがabsenceを返すまで成功にしません。
  7. LARMのrequest IDとSAAA発行attempt IDを分けます。SAAA発行IDは再送・再起動照合のkey、LARM IDは daemon内の実行証跡keyです。

共通状態とerror

  • operation stateはaccepted、running、succeeded、 failed、cancelled、result_unknownへ限定します。
  • generation停止はcancel_requested、transport_closed、 backend_stopped、stop_unknownを別fieldで表します。
  • 固定errorにはincarnation_conflict、measurement_stale、 request_digest_mismatch、subject_mismatch、 forget_in_progress、remote_stop_unknownを含めます。
  • 全照会responseへCache-Control: no-store、boot epoch、contract versionを含めます。
  • token、本文、local owner IDをerror、metric label、通常logへ出しません。

  • context.source.provision
  • context.measure
  • context.view.create
  • context.generate
  • context.attempt.cancel
  • context.forget
  • context.operation.read

credentialはsubject、Connection、Allocation、許可runtime／release、scope、期限へbindします。 Connection renewはsubjectを維持し、Allocation release、subject失効、release切替、lease epoch変更時は 古いmeasurement、View、attempt credentialを拒否します。SAAAはローカルownerとsubject fingerprintの 対応を保存しますが、その対応をLARMへ自己申告して認可には使用しません。

migrationと後方互換

  • 現行Context APIとCLIは運用互換として残しますが、Personal State製品adapterからは使用しません。 deprecated表示と移行期限はP0で固定します。
  • dependencyを持たないsnapshot manifest v1はPersonal State v2から参照しません。製品gateを開く前に 隔離または全削除し、実行結果だけを証跡へ残します。
  • subject／View／attempt linkを持たない既存inference audit recordは対象指定forgetができません。 rollout時に保持期限満了を待つか、operator承認で全recordを削除してから製品gateを開きます。
  • 既存source／attestationは自動的に製品subjectへ帰属させません。合成fixture以外は明示reprovisionを 要求し、任意IDコピーによるowner移行を禁止します。
  • 現行仕様の「Context DELETEでsnapshot unlinkとtombstone」と実装差を解消します。登録解除だけの 互換操作と、全複製を対象とするforget operationを文書とOpenAPIで明確に分けます。

監視と証跡

  • operation state、phase、runtime、結果codeだけをbounded metric labelに使用する。
  • source digest、subject、incarnation、attempt IDはmetric labelへ入れず、必要なら暗号化監査へ保存する。
  • provision bytes／tokens、measurement drift、forget phase秒数、cancel送信秒数、remote stop秒数を分離する。
  • 取消送信p95 100 ms目標と、backend停止までの時間を同じSLOに混ぜない。
  • tokenと本文を通常log、error message、test snapshot、repository証跡へ出さない。
  • live evidenceは合成ID、release digest、boot epoch、config revision、集計値だけを保存する。

SAAA側handoff

LARMの公開contractだけでは製品接続は完了しません。SAAAは同じMilestoneで次を実装し、個別issueとして 追跡します。

  • ローカルownerとLARM subject fingerprintのbindingをKeychain相当の保護領域へ保存する。
  • incarnation、attempt ID、forget IDをnetwork送信前にtransactional outboxへcommitする。
  • 応答紛失時は新IDで再実行せず、同じIDのreceiptを照会してから次状態へ進む。
  • 認証renew、release変更、request本文／tools変更時にmeasurementとViewを作り直す。
  • foreground復帰とforget後の遅延output、永続化、表示、tool副作用をattempt fenceで拒否する。
  • 登録absence、source absence、snapshot／slot safety、audit absence、remote stopを別fieldで保存する。
  • 全Providerと外部coding subprocessを列挙し、非対応経路へPersonal Stateを送らない。
  • 有限runnerの製品harnessと人手確認済みgoldを用意し、モデル自身による自己採点で代用しない。

製品接続のDefinition of Done

  1. PS-01からPS-09までのcontract、実装、typed client、negative testがすべて存在する。
  2. 合成sourceで通常、response紛失、双方再起動、forget競合、cross-subject試験が合格する。
  3. snapshot、RAM slot、推論監査を含むabsence evidenceを機械判定できる。
  4. remote stop不明時に同じslot／workerで次generationを開始しない。
  5. SAAAのoutbox recoveryとlate output／tool side-effect拒否が製品harnessで合格する。
  6. snapshot OFF／ON、cold／warm、release／tokenizer変更を含むlocal-node live canaryが合格する。
  7. bun run checkと追加conformanceが成功し、秘密dataを含まない証跡がreview済みである。
  8. Managed Context source rebuild契約と 実装完了トレーサビリティを更新し、 Context DELETE、VC-R06、VC-R08、VC-R10の判定を製品contractに合わせて再監査する。
  9. rollback rehearsal後にだけPersonal State製品gateを明示的に有効化する。
