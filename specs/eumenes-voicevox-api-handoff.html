Eumenesへ渡すプロンプト

EumenesでLARMのTTSを扱う際は、以下の既存API仕様を前提にしてください。 対象modelはvoicevox-coreです。話者キャラクター、発話スタイル、話速、ピッチ、抑揚を発話ごとに指定できます。 ここでいう「躍動」が声の抑揚を意味する場合はintonation_scaleに対応します。 アバターの画像・外見・表情・身体の動き・リップシンクを変更するAPIではありません。それらはEumenes側の表示機能として扱ってください。

接続先と認証

既存のAgent ConnectionからclaimしたTTS ProviderのbaseUrl、model、credential.tokenを使います。 通常の公開Gatewayにも同じ音声endpointがあります。個別backend portを固定せず、要求ProfileのTTS Providerを使用してください。 baseUrlが/v1で終わる場合は/audio/voicesと/audio/speechを追加し、/v1を重複させないでください。 両APIは同じTTS用Bearerを使います。以下のパスはGateway originからの表記です。 

GET /v1/audio/voices?model=voicevox-core
Authorization: Bearer <TTS Provider token>

POST /v1/audio/speech
Authorization: Bearer <TTS Provider token>
Content-Type: application/json

voicevox-coreの数値制御を使うためにLLMのmodelを変える必要はありません。 既存ProfileにTTSがなければtts-default等の登録ProfileからTTSを要求してください。 必要なProvider subsetだけを要求でき、LLMやASRを必ず同時に要求する必要はありません。

話者とスタイルの一覧

GETのJSONはdefault_voiceとvoicesを返します。voicesの各要素には次のfieldがあります。 選択肢は実際にロードされた音声モデルから生成されるため、返ってきたcatalogを使用してください。

id、display_name
保存・送信用の具体的な話者IDと画面表示名。
name、speaker_uuid、language
互換用の名前、話者UUID、言語ja。
default_style、style_id
既定スタイルの文字列IDとその数値ID。
styles
選択話者に属するスタイル一覧。各要素はid、display_name、style_id。
capabilities
speed、pitch_scale、intonation_scaleそれぞれのminimum、maximum、default。
voice_presentation
masculine、feminine、androgynous、unspecifiedの表示補助情報。
credit
選択話者のクレジット表記。

話者IDの実装例はKasukabe_Tsumugi（春日部つむぎ）、Shikoku_Metan（四国めたん）、 Zundamon（ずんだもん）、Amehare_Hau（雨晴はう）。Kurono_Takehiro（玄野武宏）、 Kenzaki_Mesuo（剣崎雌雄）もmetadata対応がありますが、追加VVMの配備状況に依存するため利用可能とは断定しないでください。 男性系・女性系の切替は具体的なvoice IDの選択で行い、pitch変更で代用しないでください。

style IDの例はnormal、sweet、tsuntsun、sexy、whisper、soft-whisper。 全話者に全styleがあるわけではありません。必ず選択voiceのstylesから選んでください。

値は発話ごとのrequestに適用されます。サーバー全体の既定値や設定を永続的に更新するAPIではありません。 Eumenes側で設定を保存し、次回以降の各requestへ反映してください。 未設定fieldは省略し、数値はJSON numberとして送信してください。NaN、Infinity、範囲外、数値文字列を送らないでください。

応答とエラー

  • 成功bodyはJSONではなく音声binary。wavはaudio/wav、pcmは24 kHz・mono・signed 16-bit little-endianです。
  • PCMのContent-Typeはaudio/pcm;rate=24000;channels=1;format=s16le。X-Audio-Sample-RateとX-Audio-Sample-Formatも参照できます。
  • X-VOICEVOX-CreditはUTF-8''に続くpercent-encoded文字列です。復号して選択話者のクレジットを表示し、春日部つむぎに固定しないでください。
  • VOICEVOXは全音声を生成してから返します。低遅延会話は既存の句単位合成・再生順序・キャンセル処理で扱ってください。
  • Gatewayの型・範囲違反は400 invalid_request。style、pitch_scale、intonation_scaleをvoicevox-core以外へ送ると400 unsupported_parameterです。他modelへこの制御仕様をそのまま適用しないでください。
  • 不明voiceやvoiceに属さないstyleは400。実装計画にはinvalid_voice_styleというcodeが記載されていますが、現在のadapter実装はdetail形式のエラーを返すため、このcodeが必ずあると仮定しないでください。
  • adapter側の入力検証は422を返す場合もあります。JSONのerror.code形式とdetail形式を区別して扱い、失敗bodyを音声として再生しないでください。
  • 合成枠がbusyなら429とRetry-After。401、Connection失効・idle解放の409、upstream障害の502とは区別してください。idle解放済みConnectionでは新しいConnectionを作成してclaimし、古いtokenを再利用しないでください。

Eumenesで利用する際の扱い

  • 設定項目は「キャラクター」「発話スタイル」「話す速さ」「声の高さ」「抑揚」。表示名を見せ、保存と送信には具体的なIDを使ってください。
  • voice変更時はそのvoiceのdefault_styleへ更新し、style変更だけでvoiceを変更しないでください。数値入力の範囲・既定値はcatalogのcapabilitiesを反映してください。
  • catalog取得失敗・選択話者の消失では保存済みIDを保持し、再取得や既定話者に戻す操作を提示してください。無言で別話者へ変更しないでください。
  • アバター画像とTTS話者の対応はEumenes側で管理してください。LARMのcatalogは画像URLや身体アニメーションを返しません。
  • 既存実装の調査時は、設定保存からPOST bodyまで各値が届くか確認し、実装済み部分と不足部分を報告してください。稼働releaseのcatalogと試聴を確認するまでは、本番での話者・style利用可能性を確定しないでください。
