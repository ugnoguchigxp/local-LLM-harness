応答形式contract

Chat Completions requestと成功response
Request Response media type 用途
stream: falseまたは省略 application/json 一括応答、structured output、従来client
stream: true text/event-stream OpenAI互換SSE client
WebSocket upgrade saaa.llm-stream.v1 SAAA Native realtime data plane

SSE requestはupstreamへAccept: text/event-streamを送り、event byte列を解釈・再構成せず 透過する。成功responseがtext/event-streamでなければ 502 upstream_response_format_mismatchとしてfail closedにする。upstreamの非2xx responseはOpenAI互換errorを伝えられるよう、元のstatusと許可headerを透過する。

Agent Connectionからの利用

  1. clientはAgent Profileを選択してConnectionを作り、ready後にclaimする。
  2. claimのbaseUrl、model、credential.tokenだけを使用する。
  3. POST {baseUrl}/chat/completionsへBearer credentialと要求する stream値を送る。
  4. JSON bodyまたはSSEの[DONE]まで読み終えてからConnectionをrenewまたはreleaseする。

claimのstreamingおよびProfileのstreamingProtocolはSAAA Native WebSocketの広告である。HTTP SSEはopenai.chat-completions.v1の標準応答形式なので、 これらのfieldがないContextStill Profileでも使用できる。

Lifecycleと安全境界

  • API token + Allocation headerと短期Provider credentialの両認証経路を維持する。
  • Provider credentialではclaimされたmodel、capability、Allocationへ固定する。
  • SSE応答中もExecutionGateのslotとService Activityのactive countを保持する。
  • client切断、Allocation失効、release、daemon drain、total timeoutをupstreamへ伝播する。
  • responseをbufferせず、upstream chunkをReadableStreamとして順次返す。
  • SSE成功応答にはCache-Control: no-cache, no-transformと X-Accel-Buffering: noを保証する。
  • Provider個別portは公開せず、Gatewayの認証・割当境界を迂回させない。

自動testと受入条件

  • stream: trueがupstreamへ到達し、Accept header、SSE media type、分割eventを維持する。
  • 成功した非SSE upstream responseを502で拒否する。
  • Agent Connectionの短期credentialとclaim modelだけでSSE completionを完了する。
  • OpenAPIがJSONとtext/event-streamの両成功responseを広告する。
  • 既存のNative WebSocket、非streaming、timeout、cancel、audit testが回帰しない。

live受入ではContextStillとNightWorkersから各一件を実行し、先頭event、[DONE]、 Connection解放、Activityのactiveからidleへの復帰を確認する。source変更だけでは配備完了としない。
