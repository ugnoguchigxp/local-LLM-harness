Managed Context source rebuild契約

Managed Contextは、認証済みprincipalへ紐づく検証済みsourceから一回限りのContext Viewを構成し、 Chat requestへ本文を挿入する。materialization modeはsource-rebuildだけとし、推論runtimeの KV stateをdiskへ保存、復元、再利用しない。

残す機能

  • sourceのprovision、digestとtokenizer identityの検証、principal単位のquota。
  • Allocation、runtime release、lease epoch、期限へbindしたContext View。
  • output reserveとsafety marginを差し引いた厳密な入力token budget。
  • 一回だけのView consume、source driftとbinding driftのfail-closed拒否。
  • Personal Stateのattempt、forget、runtime slot erase契約。

廃止した機能

  • session snapshotのsave、restore、manifest、CRC、quarantine、GC。
  • snapshot用runtime、release、route、公開model、Agent Profile。
  • snapshot root、512 GiB hard quota、watermark、最大write量のdaemon設定。
  • llama.cppのslot save pathとsnapshot conformance script。

/srv/ai/context-snapshotsはdaemonおよびworkerの書込許可対象ではなく、installerも作成しない。 既存host上のdirectoryは配備時に停止中であることを確認してから削除できる。

runtime契約

local-nodeではresident qwen-generalだけがManaged Contextを提供する。認定modeは source-rebuildであり、Context View付きChatでもprovider requestへslot固定やprompt cache強制を 追加しない。SAAAの公開model qwen3.8は同runtimeへ解決する。

受入条件

  • repositoryにsnapshot store、save/restore adapter、snapshot環境変数が残らない。
  • production registryとllama-swap groupに廃止runtimeが残らない。
  • Context APIとPersonal Stateがsource rebuildだけで全testを通過する。
  • service unitとinstallerがsnapshot directoryを作成もwrite許可もしない。
  • 既存snapshot dataを削除しても通常推論とManaged Contextが成立する。
