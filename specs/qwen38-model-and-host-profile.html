上流モデルの性質

Qwen公式model cardによれば、 Qwen3.8-27Bはpre-trainingとpost-training済みのdense causal language modelです。 coding、professional work、research、長時間のagent taskを主対象とし、thinkingの有効・無効、 reasoning_effort、過去turnのthinking保持をchat templateで制御できます。

公式model cardとlocal GGUF headerで一致を確認した主要仕様
規模 27.32B parameters。MoEではなくdense model
基本stack 64層。16回の反復ごとに、3 × Gated DeltaNet + FFN、1 × Gated Attention + FFNを配置する hybrid linear／full-attention構造
hidden・FFN hidden dimension 5,120、FFN intermediate dimension 17,408
full attention Q head 24、KV head 4、head dimension 256、RoPE dimension 64
Gated DeltaNet V head 48、QK head 16、head dimension 128
tokenizer 248,320 padded vocabulary
context native 262,144 tokens。上流はRoPE scalingで最大1,000,000 tokensへの拡張を案内する
MTP Multi-Token Predictionを複数stepで学習。local runtimeではspeculative decodeへ利用
上流modality text、image、video。vision encoderを含むVLM
license Apache-2.0

localのworker GGUF headerはgeneral.architecture=qwen35、 block_count=65、nextn_predict_layers=1を持ちます。公式が示すcore stackは64層であるため、GGUFの65という値を「core transformer層が65」と読み替えません。 これはruntime表現がnext-token prediction用要素を含むため、と解釈するのが妥当です。

ROCmFP4はartifactと専用kernelの形式名ですが、現在のprocessは -dev Vulkan0で起動します。したがって「標準ROCm backendで公式Qwen weightをserve」ではなく、 「Strix Halo向けcustom FP4 GGUFを専用engineのVulkan deviceでserve」と説明するのが正確です。 custom quant typeを含むため、vanilla llama.cppとの互換性を前提にしません。

on-demand Qwen worker

常駐modelとは別にllama-swapがworkerを必要時に起動します。worker slotは一つで、 Qwen quality、Agent、fast、比較用35Bは相互排他的です。TTLは300秒ですが、常駐 qwen-generalはswap対象外です。

これはdiscrete GPUの専用VRAMへ全てを収める構成ではありません。CPUとiGPUが同じLPDDR memoryを 共有し、amdgpuの100 GB GTT設定を通じて大きなmodelとKV cacheを載せます。観測時は常駐modelと 64K Agent workerが同時にloadされ、GTT 62,335 MiB使用、system memory 47 GiB available、GPU temperature 59 °Cでした。GPU activity 100%とsocket power約35 Wは観測瞬間のloadであり、固定仕様ではありません。

servingとnetwork境界

  • 外部clientのbase URLは同一LAN内のhttp://gnosis.local:9810/v1。
  • 認証はAuthorization: Bearer <LARM_API_TOKEN>。token値は共有文書へ書かない。
  • ChatはPOST /v1/chat/completions。非streamはJSON、streamはSSE。
  • 通常の公開modelはcoding-defaultで、常駐Qwenへ固定する。
  • Provider port 8080とllama-swap 8083はloopback-only。clientへ内部portやweight pathを公開しない。
  • Gatewayは全interfaceの9810でlistenするため、LAN firewallとBearer認証を境界にする。
  • fallbackはrequest側が明示的に許可した場合だけ。通常requestを黙って別modelへ切り替えない。

contextの意味と制限

  • modelが一度にattentionへ載せるnative windowは262,144 tokensで、入力と出力の合計です。
  • LARMは出力32,768 tokensと安全margin 4,096 tokensを別途reserveする契約を持ちます。
  • registryのsourceTokenLimit=20,000,000はManaged Contextへ登録できるsource側の上限です。 20M tokensを同時にmodel attentionへ載せる意味ではありません。
  • qwen3.8-kv-memのsession snapshotは認定済みKV状態の保存・復元であり、native attention windowそのものを20Mへ拡張する機能ではありません。
  • 常駐runtimeはsource rebuildのみ、quality workerはsource rebuildとsession snapshotを認定します。

別のLLMへ渡す短縮context

We host Qwen3.8-27B locally on a single AMD Ryzen AI MAX+ 395 (Strix Halo) machine.
Host: 16C/32T CPU, integrated Radeon 8060S gfx1151, 128 GB unified RAM, Ubuntu 26.04.1,
Linux 7.0.0-31. The iGPU uses a 2 GB visible VRAM aperture plus a 100 GB amdgpu TTM/GTT
shared-memory allocation; this is not a discrete-VRAM server.

The default resident model is a third-party quantized Qwen3.8-27B GGUF:
Qwen3.8-27B-ROCmFP4-FAST.gguf, ROCmFP4_FAST, 14,562,236,384 bytes, SHA-256
fb89c78d2be91cdb68eaaaa45b1270710bf34aa721dc1f0b9e3aa7b98d2e1da9.
It runs in a custom q38rocm/llama.cpp-derived engine on Vulkan0, fully GPU-offloaded,
with one slot, 262,144-token context, batch/ubatch 2048, K KV=q8_0, V KV=turbo4,
MTP speculative decoding up to 2 draft tokens, thinking/reasoning=auto, and temp=0.2.
The local deployment is TEXT ONLY (vision=false, audio=false), even though the upstream
Qwen3.8-27B checkpoint is a native vision-language model.

The upstream language model is dense, about 27.32B parameters, hidden size 5120,
64 core layers using a hybrid Gated DeltaNet/full-attention layout, 248,320-token padded
vocabulary, and a native 262,144-token context. Do not treat upstream benchmark scores as
measurements of this quantized local build.

LARM exposes an OpenAI-compatible gateway at http://gnosis.local:9810/v1 on the reviewed
private LAN. Use Authorization: Bearer <token>, model=coding-default, and
POST /v1/chat/completions. JSON and SSE streaming are supported. Internal providers are
loopback-only: resident Qwen on 127.0.0.1:8080 and llama-swap on 127.0.0.1:8083.

An on-demand worker pool offers a 256K UD-Q4_K_XL quality route, a 64K UD-Q4_K_XL Agent
route, and a 256K Q4_0 speed route. Only one worker-slot model is loaded at once; it can
coexist with the resident model. Public model names are coding-default (resident),
qwen3.8-kv-mem (quality/snapshot experiment), qwen-agent-worker, and qwen-nightworker.
The LARM 20M source-token limit is a managed-source budget, NOT a 20M attention window.
