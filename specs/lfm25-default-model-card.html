Controlのv3 Agent Profileカタログに上記Profileと説明を公開し、v1/modelsに公開modelを登録する。 Profileを取得してclaimに返るbaseUrl・model・credentialを使う。Ornith名による一時的な識別は終了する。 旧デフォルトselector ornith1.5Strixはlfm2.5へ解決する互換名とし、claimは正式なLFM2.5 modelを返す。画像用Ornithはornith1.5Strix-visionで明示選択する。 

{
  "model": "lfm2.5-24b-a2b",
  "messages": [{"role": "user", "content": "こんにちは"}],
  "reasoning_effort": "medium",
  "max_tokens": 4096,
  "stream": true
}

思考予算の数値は内部設定であり、利用側はreasoning_effortだけを指定する。 maxは思考予算の上限を外す意味で、max_tokens・context・要求期限は適用される。 思考と表示本文は別々に返し、初回本文までの時間には思考時間も含む。 JSON出力の形式試験は用途別に評価し、単純なcanary成功を一般的な正答率やtool選択精度と扱わない。

共有と明示選択

ContextStillはlfm2.5-contextstillからllm-contextstill-lfm25を経由して同じLFM2.5 runtimeを共有する。 優先度1000・入力枠32768・バックグラウンド実行は維持し、通常会話の優先度4000を優先する。 Ornith STRIX_LEANのornith1.5Strixとゲーム向けProfileは画像対応の明示選択肢として残す。 LFM3-1.7Bはlfm3.1.7bの明示試行用で、既定では起動しない。 LFM2.5だけを会話用のwarm floorにし、モデルは要求Profileとrouteから選ぶ。

入力計数と保持

テキスト専用のtextInput runtime policyから、配備されたengineの正確なchat入力計数APIを使用する。 公開のinput-tokens APIはclaim済みLLM Bearerで利用できる。画像用契約を偽って公開しない。 system/developer instructionの保持、出力予約、context超過、画像非対応は推論前に検査する。 保持は認証された所有者・会話scopeごとに分離し、Connectionの解放・失効時に既定scopeを失効させる。 保持を含むLFM2.5の資源予約は49.0625 GiB。重みとengineはsource repository外に置く。
