Daemon実装簡素化の決定記録

local-nodeで実際に使う運用経路を正本とし、同じ状態変更や定期処理を複数のdaemon層で実装しないための 決定です。2026年9月1日のsource監査を受け、実行時resourceと障害面を増やす重複を削除しました。

決定日
2026-09-01
対象
LARM daemon、Provider systemd unit、local-node設定
原則
一つの責務に一つのownerを置き、未使用の動的差し替え経路を持たない

採用した簡素化

責務ごとの唯一の実行経路と撤去対象
領域 正本 削除した重複
Catalog更新 versioned LARM releaseのcurrent切替とdaemon restart HTTP hot reload、swappable backend、世代別rollbackとreload中分岐
監査log retention persistent systemd prune timer daemon内の毎時prune timer
Runtime release activation immutable RuntimeReleaseManager releaseを通さないArtifactManager activation API fallback
Provider起動順 loopback listenerとlocal service dependency 外部networkを使わないunitのnetwork-online dependency
Provider設定 明示CLI引数またはglobal defaultの一方 llama-serverの同値env、llama-swapの同値model TTL、未読込TTS server block

安全性を優先して残す処理

  • 監査store起動時のpruneはcrash recoveryに必要なため残す。
  • 監査record作成時のpruneは容量と空き容量をfail closedで予約するため残す。
  • ExecutionGateは同時推論数を強制する。local-nodeのqueue上限は0なので待機timerは生成しない。
  • ASRとTTSのbody上限は、chunked bodyをframework解析前に拒否する境界として各processに残す。

冪等性修正

Agent Connectionの冪等性storeは作成時の201・202だけでなく、renewの200を含む成功した全2xx responseを保持します。同じrenew keyのretryは保存済みresponseを返し、credential generationと Allocation TTLを二重更新しません。失敗responseは保持せず、安全な再試行を許可します。
