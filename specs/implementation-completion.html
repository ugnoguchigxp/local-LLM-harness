Data Plane contract

  • Runtimeはcapabilityに対応するprotocolを一つ持ち、Registry読込時に不一致を拒否します。
  • /v1/chat/completions、/v1/audio/transcriptions、 /v1/audio/speech、/v1/audio/voicesはAllocationの固定Bindingだけを使用します。
  • requestのmodel、URL、path、service名はroutingまたはlifecycle targetになりません。
  • Gateway deadlineはqueue、body、upstream接続、response streamを覆い、client disconnect、 Allocation release、TTL満了をactive・queued requestへ伝播します。
  • production execution値は全Runtimeで同時実行1、queue 0、queue timeout 1000msです。 これは安全側の初期値であり、実測なしの待機capacityを導入しない判断です。

再起動contract

  • /healthはsoftware version、config revision、boot epochを返します。
  • 全HTTP responseはx-larm-boot-epochを返します。
  • Allocation IDはepochを含み、旧epochのIDを曖昧な404ではなく409で拒否します。
  • 同じIdempotency-Keyと正規化済みrequestの同時・逐次retryは同じ結果を返し、保持領域満杯時は entryを追い出さずfail closedします。
  • 起動後の猶予を経て、AllocationとLegacy LeaseがなくHOTなPreferredだけを停止します。 停止中はRuntimeを予約して新規Allocationとartifact変更を拒否します。
  • Resident、health不明、配備中、Allocation使用中のRuntimeはstartup回収から除外します。

Artifact snapshot contract

deploy/gnosis/models.yamlは単一GGUFをkind: file、Qwen ASRとQwen TTSをkind: snapshotとして固定します。snapshot digestはpath、bytes、SHA-256の sorted listから計算します。モデルweight自体はrepositoryへ保存しません。

  • 絶対path、親参照、空segment、重複、case-fold衝突、件数・合計bytes不一致をschemaで拒否します。
  • downloadはfile単位の一時fileへstreamし、全file検証後にsnapshot rootをrenameします。
  • staging内のsymlink、device、未列挙file・directory、manifest外のactive linkをBackendで拒否します。
  • 中断した一時snapshotはactiveにならず、既定24時間後の再試行でcleanupします。
  • activation journalはartifact kind、digest、prepared・active phaseを固定し、crash時も旧directoryを rollbackできる状態でhealth確認まで保持します。
  • Resident Qwen ASRはstaging-only、Preferred Qwen TTSだけが無人activation対象です。
  • VOICEVOXはmodel snapshotではなく外部runtime release bundleなので、model manifestから除外し、 source lockとoperator配備手順で管理します。

自動検証

repository gateはbun run checkです。CIもfrozen install後に同じcommandを実行します。 unit testはprotocol不一致、Binding曖昧性、chunked upload上限、Provider 429、queue満杯・timeout・cancel、 concurrent idempotency、旧epoch、Resident保護、snapshot hash・link・disk・中断・cleanup・rollback、lifecycle race、容量上限、strict configを含みます。

残るattended production gate

  1. 導入前のunitとcredentialを退避し、Resident Providerが稼働したままinstaller差分を確認する。
  2. larm-daemon.serviceだけをstartし、readyとResident smokeを確認する。
  3. 非機密の音声sampleでSTT、通常TTS、credit headerを確認する。
  4. Qwen TTS snapshotをstageし、明示Allocationでactivate、health、rollbackを確認する。
  5. process restart、孤立Preferred回収、queue gaugeが0へ戻ることを確認する。
  6. 実clientを段階移行し、latency、memory、error率、soak結果を別Spec HTMLへ記録する。

これらはlive service、GPU負荷、実client接続を変更するため自動実行しません。 repository実装完了は、このattended gateの成功を意味しません。
