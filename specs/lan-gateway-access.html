LARM Gateway LANアクセス方針

local-nodeのLARM Gatewayは、DHCPで変化するhost addressや特定client addressをsourceへ固定せず、 現在接続中のLANからTCP 9810へ到達可能にします。Provider port 8080–8085、SSH、その他の受信規則は この変更の対象外です。

境界

公開対象
LARM GatewayのTCP 9810のみ
接続元
適用時に検出・reviewした、既定経路interfaceのRFC1918 IPv4 prefix
認証
推論・catalog・control APIは既存のBearer token要件を維持する
対象外
Internet、IPv6、Provider direct port、SSHおよび他のservice

動的検出

  1. IPv4 default routeからinterfaceを一意に決める。
  2. そのinterfaceにあるglobal IPv4 addressが一つだけであることを確認する。
  3. addressとprefix lengthからcanonical network CIDRを計算する。
  4. CIDR全体がRFC1918範囲内であることを確認する。
  5. interface、address、prefix、UFW差分をplanに含め、全体をconfirmation digestへ固定する。

複数のdefault routeまたはglobal IPv4 addressがある場合は推測しません。operatorが経路を確認した ときだけLARM_LAN_INTERFACEでinterfaceを選択できます。planとapplyの間にaddress、 prefix、interfaceまたはUFW状態が変わるとdigestが一致しないため、変更せず停止します。

適用とrollback

plan="$(sudo deploy/local-node/scripts/configure-larm-lan-access.sh plan)"
printf '%s\n' "${plan}"
confirm="$(jq -er .confirmation <<<"${plan}")"
sudo env LARM_LAN_NETWORK_CONFIRM="${confirm}" \
  deploy/local-node/scripts/configure-larm-lan-access.sh apply

applyは検出CIDRから9810/tcpへのallowだけを追加し、既存のより限定的なhost ruleは削除しません。 rollbackはこのtoolが追加したCIDR ruleを状態記録で特定できる場合だけ削除します。

LAN prefixを許可してもアプリケーション認証は省略しません。管理外networkへ接続した後に自動適用せず、 新しいplanに表示されたinterfaceとCIDRをoperatorが確認します。
