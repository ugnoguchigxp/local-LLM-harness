SAAA Ornith 35B + Qwen 2B基本応答プロファイル

SAAAの基本応答を、常駐Ornith 1.5 35Bとsession連動Qwen 3.5 2Bの組合せへ変更する。 従来の常駐Qwen 3.8 27Bは外し、必要なbackground workload向けの明示的な llama-swap Runtimeとしてのみ残す。本書はrepository desired stateを定義するもので、 production serviceのinstallまたはrestartを記録するものではない。

決定

基本応答を構成するLLM Runtimeの役割、context、lifecycle、予約memory
役割 Runtime Context Lifecycle 予約
通常会話・推論・coding Ornith-1.5-35B-A3B ROCmFP4、MTP n4/p0.6 131,072 token resident、1 slot 40 GB
短応答・相槌判断・単純Tool選択 Qwen 3.5 2B Q4_K_M 65,536 token Agent Connection session中にlease 8 GB

Ornith artifact gate

resident Runtimeは2026-08-24 MTP refresh後のartifactだけを使用する。SHA-256は 0f907917a1bfe4e0ca0d281e5709dcf34b6277063e94fab29491bb5c80fda696である。 旧artifact b42fb74cd32ce3ab5fc0b10214ae7b4030d852f49b749dcdd0e5ad6b35e1510fは MTP評価にもproduction activationにも使用しない。

Agent Profile contract

canonical profileはsaaa-conversation-ornith15とし、Ornith、Qwen 2B、Qwen ASR、 VOICEVOX、multilingual E5を一つのConnection TTLへ束ねる。旧SAAAとの復旧経路である saaa-qwen38はGemma 4構成のfrozen legacy profileとして保存し、意味を変更しない。 SAAAは新profileがcatalogに存在しない場合だけlegacyを選び、claimにbackchannelが なければ全LLM処理をlegacyのllmへ送る。

Routingと分離

  • llm-defaultとSAAAのmain LLM routeはornith-generalだけへ解決する。
  • Qwen 2BはSAAA専用routeから解決し、Agent Connection release後はunload可能にする。
  • Qwen 3.8 workerはContextStill、NightWorker、明示的speed routeのために残す。
  • Gemma 4 profileは比較・fallback検証用の明示選択肢として残し、基本セットには含めない。
  • Legacy profile IDはin-placeで別モデルへ転用せず、rollback可能な契約として凍結する。

Activation gate

  1. registry、Agent Profile、systemd unit、release manifestの静的検証を通す。
  2. production適用前に現行unitとrelease pointerをoperator-owned backupへ保存する。
  3. Ornith SHA-256を再検証し、MTP OFF baselineの後にn4/p0.6を測る。
  4. 128–512 output tokenでTTFC、prompt処理、decode、MTP acceptance、RAM、GPU使用率を記録する。
  5. SAAAからOrnith main応答、Qwen 2B短応答、ASR、TTS、Embeddingを同一sessionでcanaryする。

現時点のlocal MTP実測は公開目標の100–106 tok/sへ未到達である。設定切替はモデル速度の 合格を意味しないため、性能差は別のbenchmark証跡として継続追跡する。
