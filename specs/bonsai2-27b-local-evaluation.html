Ternary Bonsai 2 27B 実機評価 Phase 1–3

1. Executive Summary

  1. Ryzen AI MAX+ 395 / Radeon 8060S 上で Bonsai 2 PQ2_0、PTQ1_0、第三者 MTP、第三者 DFlash2 の実動作を確認した。
  2. stock llama.cpp は PQ2_0 / PTQ1_0 と Bonsai 固有 Hadamard 処理に非対応であり、PrismML 系の専用 runtime が必要である。
  3. 素の PQ2_0 decode は 21.7 tok/s で、同条件の Qwen 3.8 27B（13.8 tok/s）より 57%速い。
  4. MTP 付き Bonsai は 128 token で 33.9 tok/s、2048 token で 39.8 tok/s を記録した。
  5. 現行 Qwen MTP の 26.1 tok/s に対し decode は速いが、Bonsai MTP の TTFT は約 559 ms で Qwen の約 239 ms より遅い。
  6. PQ2_0 の prefill は 1K–16K で Qwen より約 25–27%遅く、長い会話履歴を毎回読む用途では不利である。
  7. PQ2_0 は現行 Qwen artifact の 49.5%、PTQ1_0 は 40.8%のファイルサイズであり、「現行 model の 1/3以下」という仮説は成立しない。
  8. 第三者 MTP は実用候補、DFlash2 は追加約 2.06 GBに対して MTP より遅く、この実機では第一候補にしない。
  9. Phase 1–3 の速度ゲートは通過し、AGI論考1件ではQwenが文章品質で優位だった。50問 A/B、128K context、agentic coding は未評価である。
  10. 全面移行はせず、別 runtime・別 Provider として追加し、ContextStill 作文 A/B を次の採用ゲートにする。

Qwenは全体を完結させ、日本語も概ね自然だったが、「ヤン・レクサス」という人名誤記と、実在を確認できない 「ジャコブズの補完性／ジョナサン・ジャコブズ」を事実のように記したため、事実精度を低く採点した。 Bonsaiは「能力の民主化と責任の非対称性」という中心主張が明快だった一方、 構造的变化、個人 맞춤형、境界線が模糊、 是不相容れなど中国語・韓国語断片が混入し、最後は結論途中で切れた。 この1件では、速度はBonsai、納品可能な文章としての品質はQwenを選ぶ。

長文生成時のmemory

Bonsaiは amd-smi process でprocess帰属memory 9.56 GB（8.91 GiB）、うちGTT 9.35 GB、Linux RSS 1.61 GBだった。Unified Memoryのためこれらは単純加算しない。 QwenはVulkan processで amd-smi process に個別表示されず、生成中のhost全体はVRAM + GTT 29.56 GBだったが、常駐ASR / TTS等を含むためQwen単独値として扱わない。Qwen weight artifactは14.56 GBである。比較可能な根拠から、Bonsaiのmodel実行memoryが小さいことは支持されるが、今回のQwen単独runtime memoryは未確定である。

最初のQwen試行ではthinkingを無効化しなかったため、3000 tokenを非表示reasoningに使い切り、本文が空になった。 150.15秒を要したが作文比較から除外した。Provider化では enable_thinking=false を明示する必要がある。

5. Long Context Result

16K prefill速度までは測定済み。32K / 64K / 128K / 256K の速度、peak memory、検索品質は未測定である。 初期ゲートでBonsaiのprefillが約25%遅いことが判明し、全長を3構成×3回実行する前に一度結果をレビューする方針とした。 数値は推測で補完しない。

6. SAAA suitability

短い会話では現行QwenのTTFTが有利であり、Bonsaiを即時の全面代替にはしない。Bonsai MTPは生成開始後34–40 tok/sを示し、 30 tok/s基準は満たした。約8.9 GBのshared GPU memoryで動作したため他model同時常駐の余地は大きいが、 ASR / TTS / embedding / 軽量LLMとの同時負荷試験と常時稼働時の電力量は未実施である。

7. LARM integration

  • 既存Qwen Providerをresident defaultとして維持する。
  • Bonsaiは専用 Prism runtime、専用port、専用model directory、固定SHA-256を持つ別Providerにする。
  • 初期候補は PQ2_0 + MTP。PTQ1_0は小さいがdecode優位が小さく、DFlash2はmemory効率でMTPに劣る。
  • stock llama.cpp互換を宣言せず、runtime capabilityに bonsai-hadamard と speculative方式を明示する。
  • 第三者 speculative artifact は自動取得せず、明示的opt-inとprovenance記録を必須にする。
  • 今回LARM registryや既存起動設定への変更は行っていない。
