正式なv1応答スキーマ改訂：2026-10-31

protocolとcontractVersionはlarm.visual-perception.v1、endpointはPOST /v1/vision/perceiveを維持する。CPU分岐の欠落を廃止し、execution.decoderDtypeとexecution.visualTokensを両方必須とする。非搭載decoderにnullを許すのはCPU説明専用分岐だけである。この改訂はdecoderDtypeをstringのみとする利用側に明示的な移行を要する。従来の利用側でそのまま受理できるとは主張しない。公開OpenAPIのVisualPerceptionResponseを機械可読な正本とする。

通常検出の公開入口

既存OCR ingressを登録service IDを検証する共通実装へ拡張する。installerの--service-id object-recognition-hostで専用unit・config・receiptを作成する。登録済みgatewayからupstreamを解決し、既存OCR設定は変更しない。LANのprivate addressだけで待受し、同LANのsource CIDRだけをfirewallで許可する。

GET /hosting/status、POST /api/analyze、GET /api/jobs/{id}、POST /api/jobs/{id}/cancelを転送する。Authorization以外のowner assertion、cookie、転送headerを渡さず、既存gatewayの共通LARM API token認証を使用する。status参照ではworkerを起動しない。gateway再起動・boot後の復帰はRequires、PartOf、WantedByで維持する。
