稼働releaseは今回のrepository改修より前の版で、旧192.168.0.65を広告します。 これは廃止対象であり、current worktreeのrequest-origin contractをproductionへ反映するには 通常のclean release gateが必要です。

原因と境界

観測された4ミリ秒の失敗は、SAAA processにLARM_API_TOKENが存在せず、HTTP request前のClient preflightで停止したものです。LARM daemon、LAN descriptor、推論modelの失敗では ありません。token値をsource、文書、chat、通常logへ埋め込む修正は行いません。

Clientは未認証livenessとcredential不在を分離して報告し、Agent Connection APIだけを api_token_missingでfail fastさせます。credentialの実値はSAAA側の承認済みsecret storeからprocess起動環境へ注入する必要があります。

追加調査では、旧releaseが固定したLAN addressと現在のDHCP addressが不一致となり、claim後の data plane接続が到達不能になることも確認しました。また30秒で停止したResident要求はslot内で 約31 token/s、940 tokenまで生成しており、推論停止ではなく、無制限reasoningと非stream応答が Client timeoutを超えたものです。固定addressを廃止し、低遅延要求はbounded generationまたは streamingを使用します。

Network address policy

local-nodeのinterface addressはDHCPで管理し、LARM repositoryから固定addressを配備しません。 初期Control API discoveryにはmDNS/DNS名またはoperatorが発見した現在のaddressを使用します。 旧/etc/netplan/99-larm-static-ip.yamlが残るhostでは、 deploy/local-node/scripts/restore-dhcp.shがattended netplan tryを行い、 dynamic address、DHCP default route、gateway到達性を確認してからoverlayを除去します。検証失敗時は overlayとnetwork stateを復元します。

2026-08-29T12:09:56Zまでにlocal-node上で、TTL 300、fallback無効、 existing-onlyの条件によりProfile取得、create、poll、claim、semantic health、OpenAI-compatible SSE、DELETEを完走しました。SSEは非空dataと[DONE]を確認し、DELETEは204、解放後の Provider tokenは401、対象runtimeは既定idle cleanupのbounded時間内にCOLDとなりました。

SAAA送信元192.168.0.76からの最終canaryは未実施です。完了条件はSAAA processへ credentialを注入し、同じrevisionを観測してauthentication failureなしでこのlifecycleを再実行することです。

追加のlocal-node検証では、Resident直接推論がHTTP 200、初回応答0.68秒、SAAA形式の短期tokenと Gatewayを使った可視応答がHTTP 200、0.15秒で完了しました。オンデマンド35Bは7.28秒で起動し、 stream完了後にConnection、Allocation、Leaseを解放してCOLDへ戻りました。current worktreeの request-origin単体・統合testはDNS名、DHCP address、loopback拒否、originを跨ぐidempotency conflictを 検証しています。
