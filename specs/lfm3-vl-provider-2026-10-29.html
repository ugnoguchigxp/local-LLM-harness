LFM3-VL-2Bのオンデマンド画像Chat Provider

LFM3-VL-2Bを明示profile lfm3-vl-2bとして追加する。既定の会話、OCR、WeVisOne、画像生成は変更しない。Chat Completionsの画像data URLに対応するが、WeVisOneの物体位置・マスクを含むvisual-perception APIと同等ではない。

契約と管理

Agent Profile selector lfm3-vl-2bからroute llm-lfm3-vl、runtime lfm3-vl、llama-swap model lfm3-vl-2bへ解決する。Providerはopenai.chat-completions.v1とllm.visionを提供する。画像契約はPNG・JPEG・BMPのdata URL、最大8画像、入力token計数APIとSSEを含む。音声入力や画像生成には対応しない。

CPU 8 threads、8192 token、出力予約512、安全余白256、同時1要求。常駐最小数0、接続のidle release 60秒、解放後runtime idle TTL 60秒。既存の会話モデルのswap groupには属さない。使用中はleaseと実行参照で保護する。重みはQAD-Q4_0とF16投影器で、推定memory 4 GBは上限ではない。

準備と検証

画像入力の事前token計数を提供するllama.cpp revision 19cce6919992fdffd92e0ac152caaf1e2b8f254eと固定差分を使用する。deploy/local-node/scripts/prepare-lfm3-vl-engine.shは既存の隔離されたpatched worktreeとRelease buildを検証し、repository外の独立runtimeへ出力する。元worktreeを編集しない。

実環境のrelease commit 6f9321ea6774b08e46abcf4064e6c1a9559ab502を基点に既存の専用視覚APIを維持した候補で検証した。隔離LARM・llama-swapを用い、画像1枚と2枚のChat応答と公開token計数の一致、SSE終了、外部URL拒否、接続解放と資格失効を確認した。runtime idle TTLを3秒に短縮した試験では解放後3.5秒でworker停止を確認した。正式60秒での停止、artifact release管理、および既存consumerとの接続は正式配備後の確認対象である。

画像説明APIへの採用

visualPerceptionのvision ProviderはCPUのLFM3-VL-2Bをオンデマンドで起動し、従来の/v1/vision/perceive入口でdescribeを受け付ける。モデル名は接続claimが返すlfm3-vl-2bを使用する。従来の検出、位置、OCR、マスク等は提供せず、要求にはエラーを返す。専用のOCR・物体検出サービスは維持する。

入力は既存のPNG、JPEG、WebP data URLを検査しEXIF正規化後にローカルのllama.cppへ渡す。文章、切断状態、画像寸法、CPU実行情報を返す。画像ファイルは保存しない。利用終了後の接続releaseでProviderを停止し、無通信60秒でも解放対象になる。systemd user unitはdeploy/local-node/scripts/install-lfm3-vl-perception.pyで独立して準備する。

隔離LARMで同一APIのclaimと画像説明を2回検証し、準備2.54〜2.78秒、説明7.89〜7.93秒、release後の停止と資格失効を確認した。未対応taskの拒否も実画像で確認した。記録は/srv/ai/evidence/lfm3-vl-perception-20261029。現実環境への切替と既存利用者の移行は別途確認が必要。

旧WeVisOneモデルの削除は実環境切替後に行う。Qwen3-VL-8Bの本体はQwen-Image 2.1画像生成サービスのencoderとしても参照されており、画像説明からの引退だけでは削除できない。

2026-10-31：execution応答契約の修正

採用時のCPU用execution分岐にはdecoderDtypeとvisualTokensの必須契約との不一致があった。正式なスキーマ改訂と移行・検証結果に従い、非搭載pixel decoderは必須のnull、visualTokensは同一入力に対するengineのMTMD実測値とする。省略や推測値による補完は行わない。旧string限定の利用側には明示的な移行が必要。
