SAAA・ContextStill向けAgent Connection provide移行プロンプト

以下の二つのsectionは、それぞれのrepositoryを担当する実装agentへそのまま渡せる改修依頼である。 LARMは旧request入力agentProfileとexplicitAgentProfileを廃止した。 Consumerは公開selectorをprofileとしてPOSTし、具体Agent ProfileとProvider構成を作成responseから受け取る。

実装済みLARM contract

  • GET /v3/agent-profiles?profile=<selector>は任意の事前照会であり、状態を変更しない。
  • POST /v1/agent-connectionsの必須profileがprovide、起動、確保要求である。
  • 旧入力fieldを含むrequestは400 invalid_requestになる。
  • Prefer: wait=Nは1〜300秒。期限内readyは201、準備継続は202となる。
  • 任意のexpectedCatalogRevisionが不一致ならAllocation作成前に409となる。
  • responseは公開profile、解決後agentProfile、providers、補助 servicesを返す。各Providerにはprotocol、endpoint、model、readiness、claimableが含まれる。
  • SAAA提供中のContextStill要求は409 provider_conflictとRetry-Afterを返す。

SAAA向けプロンプト

SAAAをLARMの新Agent Connection provide契約へ完全移行してください。

前提:
- LARM側では旧request field agentProfile / explicitAgentProfileは廃止済みです。
- 通常会話selectorはSAAA、画像sessionはSAAA-w-Image、音楽sessionはSAAA-w-musicです。
- GET /v3/agent-profilesは任意のdiscovery、POST /v1/agent-connectionsがprovide要求です。

実装要件:
1. Connection作成bodyは次の形にする:
   {"profile":"SAAA","audience":"saaa-desktop","client":"saaa-desktop","ttlSeconds":900,"allowFallback":false,"deploymentPolicy":"existing-only"}
2. agentProfileとexplicitAgentProfileをrequest型、serializer、fixture、設定migrationから削除する。
3. createにはPrefer: wait=300と再送可能なIdempotency-Keyを付ける。
4. 事前discoveryを行った場合だけexpectedCatalogRevisionへ取得revisionを渡す。GETなしの直接POSTも許可する。
5. 201ではstatus=readyと全Providerのclaimable=trueを確認する。202ではLocationの同じConnectionをbounded pollする。
6. response.profileが要求selector、response.agentProfileが非空であることを検証する。具体Profile IDを次回POST入力へ使わない。
7. providersをnameで索引化し、通常SAAAではllm、backchannel、asr、tts、embeddingの5件を必須にする。
8. protocol、endpoint、modelを厳密検証する:
   llm/backchannel: openai.chat-completions.v1, /v1/chat/completions
   asr: openai.audio-transcriptions.v1, /v1/audio/transcriptions
   tts: openai.audio-speech.v1, /v1/audio/speech
   embedding: larm.embedding.v1, /v1/embed
9. claim後は短期credential、baseUrl、modelを実行時の正本にする。create responseとclaimが矛盾したら推論しない。
10. SAAA-w-Imageはservicesのimage、SAAA-w-musicはservicesのmusicを検証する。servicesはclaim対象ではない。
11. HTTP切断を起動取消として扱わない。同じIdempotency-Keyで再取得し、明示取消はDELETEだけで行う。
12. 自己診断をTCP/HTTP到達、discovery、create、semantic readiness、claim、実推論に分ける。4xx契約失敗を「到達不能」と表示しない。
13. API tokenとclaim tokenをログ、診断JSON、SQLite、設定画面へ保存しない。

必須test:
- POST bodyがprofile=SAAAを含み、旧二fieldを含まないこと。
- discoveryなしの直接POSTが201 readyへ到達する統合test。
- Prefer wait期限内の201と、期限超過時の202→poll→readyを検証するtest。
- responseの5 Providerを順序非依存で検証し、欠落、重複、protocol/endpoint/model不一致を拒否するtest。
- SAAA-w-Image / SAAA-w-musicのselectorとservicesを別testで固定する。
- revision不一致、terminal 503、idempotency conflictを型付きエラーへ写像するtest。
- create、claim、LLM、backchannel、ASR、TTS、embedding、renew、release、credential失効まで通すE2E。
- 自己診断がnetwork成功とcreate契約失敗を別項目で表示する回帰test。

完了条件:
- 旧request生成経路と旧fixtureがrepository内に残っていない。
- 通常・画像・音楽sessionが新selectorだけで作成される。
- 隔離daemonまたはlive LARMでprovideからreleaseまで完走する。
- 実装、test、仕様、自己診断表示を同じ変更で更新する。

ContextStill向けプロンプト

ContextStillをLARMの新Agent Connection provide契約へ完全移行してください。

前提:
- LARM側では旧request field agentProfile / explicitAgentProfileは廃止済みです。
- ContextStillの公開selectorはcontextStillです。
- SAAAがprovide中なら409 provider_conflictです。これはpendingではなく今回jobのrejectedです。

実装要件:
1. Connection作成bodyは次の形にする:
   {"profile":"contextStill","audience":"same-host","client":"contextstill","ttlSeconds":300,"allowFallback":false,"deploymentPolicy":"existing-only"}
2. agentProfileとexplicitAgentProfileをrequest型、serializer、fixture、設定migrationから削除する。
3. createにはPrefer: wait=300とjob単位のIdempotency-Keyを付ける。
4. GET /v3/agent-profiles?profile=contextStillは表示や事前検証が必要な場合だけ使う。GETなしの直接POSTも許可する。
5. discovery時だけexpectedCatalogRevisionを送り、不一致なら再discovery後に新しいkeyで再評価する。
6. 201ではreadyを確認する。202だけをpending/probingとしてLocationからbounded pollする。
7. response.profile=contextStill、agentProfile非空、providersがllm一件であることを検証する。
8. llmはprotocol=openai.chat-completions.v1、endpoint=/v1/chat/completions、model非空、ready時claimable=trueを必須にする。
9. claim後は短期credential、baseUrl、modelを正本にし、create responseとの不一致時は推論を開始しない。
10. 409 provider_conflictは今回jobのrejectedとして扱い、poll、fallback、同一job内retryを行わない。
11. Retry-Afterを記録し、次job境界で新しいIdempotency-Keyにより再評価する。busy loopしない。
12. SAAAより優先して資源を奪う処理をConsumer側へ追加しない。優先順位とpreemptionはLARMに委ねる。
13. tokenをログ、DB、settings response、成果物へ保存しない。

必須test:
- POST bodyがprofile=contextStillを含み、旧二fieldを含まないこと。
- discoveryなしの直接POST、201 ready、202→poll→readyを検証する統合test。
- responseのprofile、agentProfile、endpoint、protocol、model、claimableがclaimまで伝播するtest。
- 409 provider_conflictをrejectedへ写像し、poll、fallback、同一job内retryを行わないtest。
- Retry-After後または次jobで新しいIdempotency-Keyを使用するtest。
- revision不一致、unknown selector、terminal 503、timeoutを区別するtest。
- claim、実推論、renew、release、credential失効まで通すE2E。
- Rust resident lifecycleを維持し、TypeScript workerへ動的LARM targetを渡さない回帰test。

完了条件:
- 旧request生成経路と旧fixtureがrepository内に残っていない。
- SAAA active中のjobがprovider_conflictとして安全に終了し、成果を一回だけ保存する。
- SAAA非active時はprovideからreleaseまで完走する。
- 実装、Rust test、設定migration、管理UI、仕様を同じ変更で更新する。
