ContextStill向けLARM HTTP Provider live改善方針

2026-09-06のlive未到達調査で確認したrelease不一致を解消し、同じ種類の不成立を配備時に検知するための改善方針です。 ContextStill専用endpointは追加せず、Service Activity、Agent Connection、OpenAI互換Chat Completionsという既存の汎用contractを強化します。

最優先目標
対応済みreleaseをliveへ配備し、ContextStill ProfileのJSONとHTTP SSEを実通信で受入する
再発防止目標
release identity、公開contract、Provider意味互換、client設定の四層でfail closedにする
Repository実装状態
2026-09-06にSSE semantic readiness、汎用HTTP Agent smoke、release後contract gateを実装し、 production Provider資産を使うshadow canaryまで完了。live配備はsudo認証待ち
対象外
自動本番配備、ContextStill専用API、Provider portのLAN公開、静的Providerへの暗黙fallback

固定する判断

  1. 今回の復旧は新たなSSE実装ではなく、対応済みcommitまたは承認済み後続commitのtransactional releaseで行う。
  2. openai.chat-completions.v1は非streaming JSONとHTTP SSEの両方を含む。 Native WebSocketのstreamingProtocolをHTTP SSE対応判定に使わない。
  3. /healthと/readyだけでは配備成功にしない。Activity、Profile、短期Bearer、 claim model、JSON、SSE、releaseまでを一つのlive contract gateにする。
  4. source HEADとliveの単純な不一致は即時自動配備の理由にしない。承認済みdesired commitとlive releaseCommitの不一致を警告・停止条件にする。
  5. clientはfail closedを維持するが、待機理由を一つの waiting_for_dynamic_providerへ潰さず、運用者が故障層を判別できる状態を公開する。

P0: 即時復旧

  1. 調査記録をreviewしてcommitし、release元worktreeをcleanにする。
  2. release-larm.sh planを再実行し、target commit、現在のrelease、cleanup対象、確認digestを operatorが照合する。
  3. 既存のtransactional applyを実行し、失敗時の自動rollbackを維持する。
  4. /healthのreleaseCommitとconfigRevisionが候補manifestと一致し、 bootEpochが旧値から変化したことを確認する。
  5. ContextStill hostと同じLAN経路から/v1/activityが200、 /v2/agent-profilesにcontextstill-backgroundが一意に存在することを確認する。
  6. Activityがidleのときだけ同ProfileをexplicitAgentProfile: true、 allowFallback: false、deploymentPolicy: existing-onlyで作成する。
  7. claimされたbase URL、model、短期Bearerだけで、短いJSON completionとHTTP SSE completionを行う。 SSEは有効なdelta一件以上と終端data: [DONE]を必須にする。
  8. Connectionを解放してtoken失効、active allocation 0、workerのidle回収を確認してから、ContextStillの LLM必須jobを一件だけ実行する。
  9. 次job境界でActivityを再確認し、旧127.0.0.1:44448への接続が0件であることを確認する。

P1: live contract gate

現在のsmokeはResident AllocationのJSON/SSEと、SAAA ProfileのNative WebSocketを別々に検証する。 非Nativeのcontextstill-backgroundを、Agent Connectionの短期credentialでHTTP SSEまで通すgateがない。この空白を汎用HTTP Provider smokeで埋める。

新しいgateはprofile、audience、期待model、期待release identityを引数化し、Native WebSocket広告の 有無に依存せず次を検証する。

  • desired commitと/health.releaseCommit、manifest config revisionの一致
  • Activityのstrict schema、freshness、idle条件
  • Profileのselection policy、deprecated、protocol、public model、Audience
  • create、ready poll、claim、provider health、JSON completion、HTTP SSE completion
  • SSEのstatus、media type、event区切り、chunk JSON、delta、finish、[DONE]
  • release後のtoken 401、Allocation・execution slot漏れなし、worker idle回収

tokenはprocess memoryまたはmode 0700の一時directoryだけで扱い、標準出力、journal、証跡JSONへ 書かない。cleanupはsignalと途中失敗を含む全経路で実行する。

release script自身には、推論を伴わない軽量post-activation contract検査を追加する。release identity、ready、Activity、catalog revision、設定済みProfile全体のいずれかが候補releaseと異なる場合は 自動rollbackする。OpenAPIのtext/event-stream広告はrelease前の自動testで固定する。 モデルloadを伴うHTTP Provider smokeはattended canaryとして直後に実行する。

P1: Provider意味互換の強化

現行のLLM semantic readinessはstream: falseの一token JSONだけを検証するため、Providerが HTTP SSEを返せなくてもclaim可能になる。Chat Completions Providerには、短いSSE probeを追加する。

  • stream: true、max_tokens: 1、Accept: text/event-streamを使用する。
  • 200とSSE media type、bounded bytes、valid UTF-8、少なくとも一つのchunk、[DONE]を検証する。
  • JSON probeとSSE probeが両方成功した場合だけready: trueにする。
  • probe結果は現行と同様に短時間cacheし、同時health requestは一つへ集約する。
  • timeout、client切断、Allocation失効時はupstream bodyをcancelし、execution slotを必ず解放する。

Gatewayは引き続きSSE bytesを再構成せず透過する。runtime中の形式違反はstreamをabortし、metricsへ boundedなreasonを記録するが、不正なeventを補正したり[DONE]を捏造したりしない。

P1: release driftと待機理由の可観測化

  • operatorが承認したdesired commitをrepository外のroot管理stateへ記録し、live releaseCommitとの差をread-only auditで検出する。
  • source HEADとの差だけでは自動切替しない。未reviewのcommitを本番へ流さない。
  • release_identity_mismatch、activity_unauthorized、 profile_missing、connection_rejected、sse_contract_failureを区別する。
  • ContextStillはQueueをfail closedで保持しつつ、現在理由、最終HTTP status、失敗段階、最終成功時刻を secretなしで状態表示する。
  • 同一失敗を毎pollでlogせず、状態遷移時と低頻度の継続警告だけを記録する。
  • LARM metricsにはstream request結果、upstream media type mismatch、client cancel、timeout、 release identityをbounded labelで追加し、request IDやConnection IDをlabelにしない。

P1: ContextStill側の改善

  • resident daemonの実効設定でProvider kind、control host、Profile、Audienceをstartup時に記録する。
  • /v1/activityへqueryとbodyを送らず、optional bearerは設定時だけ送る。
  • 401、404、invalid schema、stale activityをidleへ読み替えず、静的Providerへfallbackしない。
  • claimのbase URL、model、tokenを上書き・永続化せず、Connection世代をまたいで再利用しない。
  • SSE response bodyの完了または失敗までtimeoutを維持し、次jobの前にActivityを再確認する。
  • 再試行は上限付きexponential backoffとjitterを使い、Queue item自体はclaimしない。

導入順序

  1. 復旧: 現行候補を配備し、手動のContextStill HTTP canaryを完了する。
  2. gate実装: 汎用HTTP Provider smokeと軽量post-activation検査をrepositoryへ追加する。
  3. readiness: SSE semantic probeを追加し、失敗fixtureとcancel・timeout testを固定する。
  4. client可観測化: ContextStillの待機reasonと実効設定表示を追加する。
  5. 定期確認: 低頻度canaryを実行し、正常時は通知せず、変化・失敗時だけ通知する。

P1実装を待ってP0復旧を遅らせない。最初のlive受入はattendedで行い、受入後にだけContextStillの Queueを一件ずつ再開する。

2026-09-06 Repository実装記録

  • packages/core/src/openai-sse.tsにboundedなOpenAI SSE検査器を追加し、valid UTF-8、SSE field、chunk JSON、meaningful delta、finish reason、終端[DONE]を検証する。
  • LLM semantic readinessをJSONとSSEの二段probeへ変更し、同じ固定Bindingとexecution slotの中で両方が成功した場合だけclaim可能にした。
  • deploy/local-node/scripts/smoke-agent-http.tsを追加した。Profile discovery、create、ready、claim、semantic health、JSON、SSE、release、token 401、最終Activityを secret-freeな一つの結果として検証する。途中失敗でもConnectionを解放する。
  • deploy/local-node/scripts/verify-live-contract.tsをrelease後gateへ組み込み、候補manifestと live identity、Activity、Agent Profile全体の一致を確認する。新releaseの不一致は既存のtransactional rollbackを発火し、旧releaseへのrecovery確認は後方互換のidentity・ready検査を使う。

ContextStill向けattended canaryは次のsecret-free設定で実行する。

LARM_BASE_URL=http://<local-node-lan-address>:9810 \
LARM_AGENT_PROFILE=contextstill-background \
LARM_AGENT_AUDIENCE=saaa-desktop \
LARM_AGENT_CLIENT=contextstill \
LARM_EXPECTED_MODEL=qwen-agent-worker \
LARM_EXPECTED_RELEASE_COMMIT=<approved-commit> \
bun run smoke:agent-http

最終受入条件とrollback

  • desired commit、live release、catalog revision、boot epochが証跡上で一貫する。
  • ContextStill hostからActivity、Profile、create、claim、JSON、SSE、DELETEがすべて成功する。
  • SSEは有効deltaと[DONE]を受信し、成功JSONをSSE成功として扱わない。
  • Connection解放後にtokenが拒否され、active workload、Allocation、execution slotが0へ戻る。
  • ContextStillのLLM必須jobが一件完了し、次job境界でActivityが再評価される。
  • Provider portおよび旧127.0.0.1:44448へのclient接続が0件である。

release identity、Activity、Profile、Provider health、JSON、SSEのいずれかが失敗した場合はQueueを fail closedのまま維持する。LARM releaseを既存のtransactional rollbackで戻し、client側の静的 Providerへ暗黙fallbackしない。
