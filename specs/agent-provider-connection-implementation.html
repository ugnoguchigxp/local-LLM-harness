Agent worker構成と実機校正

既存の256K一般worker contractは変更せず、Agent Connection専用に64Kの qwen-worker-agentとornith15-35b-agentを追加しました。両方は qwen-worker-slotへ所属し、同時には一方だけを実行します。常駐 qwen-generalは別processのままです。

現行Agent Profile catalogはHTTP contractを満たすcoding-defaultを既定として 広告します。workerと35BのRuntime・Routeは比較用途として残しますが、自動選択対象には 含めません。

最初の32 GB見積もりは、live accelerator headroomが30.56 GBへ変動した時にcold startを拒否しました。 同じ実機で35B worker cgroup peakが18.2 GBだったため、10 GB弱の余裕を残す28 GBへ校正しました。 静的node上限と最新telemetryの両方を通過しなければ起動しない既存admission規則は維持しています。

35B反復推論regression

Ornithは初回probeとtaskに成功した後、成功cache失効後の二回目probeでq38rocm engineが終了しました。llama-swapを介さず同一commandを再現し、prompt cacheが以前のsequenceを 再利用する際のsequence除去assertを終了原因として確認しました。

一般35BとAgent 35Bの両commandへ-ctxcp 0、-cram 0、 --no-cache-prompt、--no-cache-idle-slotsを固定しました。変更後は初回task、 11秒後のcache miss semantic probe、二回目taskが同じprocessで成功しました。healthのために長文を 生成せず、各live probeは引き続きcompletion一tokenだけです。

SAAA接続contract

Audience saaa-desktopをnetwork: host-private、advertised URL sourceをrequest-originとしました。SAAAはmDNS/DNS名または現在のDHCP addressへ 直接接続し、control APIを既定port 9810で呼びます。LARMは受理したConnection作成requestの originをcanonicalな/v1 URLとしてclaimへ固定します。 routing設定はhostだけで、長期LARM_API_TOKENはlocal-node SAAAでは任意です。 claimされたProvider tokenはConnection TTL内だけの扱いです。

SAAA固有のclaim fieldは追加していません。既存のbaseUrl、model、 credential.tokenをOpenAI clientへそのまま渡します。Provider portはloopbackのまま、 production LARMだけが0.0.0.0:9810でlistenします。非loopback listen時はAPI・management tokenがないとdaemonが起動せず、UFWはreview済みLAN CIDRだけを許可します。

saaa-desktop claimはrequest originと同じhost・portのOpenAI互換HTTP baseUrlを返します。ローカルLANでは短期Provider token、origin binding、許可CIDRを 境界とし、LAN境界外ではtls AudienceとHTTPSを使用します。

local-node live E2E

実model artifact、常駐27B process、repositoryのllama-swap設定、一時LARM daemon、公式 OpenAI JavaScript client 7.8.0を使用しました。E2E用API keyとsigning keyは一時値で、証跡へ 保存していません。

  1. coding-defaultを同期200・readyで作成し、claimのsemantic healthを確認した。 llama-swapのrunning memberは空のままで、常駐27Bだけを使用した。
  2. coding-workerを202からreadyまでpollし、qwen-agentの起動を確認した。 常駐27Bと追加27Bへ公式OpenAI clientのstream taskを同時送信し、両方で非空completionを得た。
  3. scoped tokenで別public modelを指定したrequestが400 model_mismatchとなり、固定 Binding以外へ転送されないことを確認した。
  4. 追加27Bをreleaseし、Audience saaa-desktopで deep-reasoning-35bを作成した。running memberが ornith15-35b-agentへ置換され、claim descriptorだけでstream taskを完了した。この初期E2Eでは当時のLAN addressを返したが、固定address contractは後続の 後続の動的接続改修で廃止した。
  5. 11秒待って成功cacheを失効させた後、Provider healthがlive semantic probeを実行して200、 ready: true、cached: falseを返した。続く二回目taskも同じ35B processで完了した。
  6. 全ConnectionをDELETEし、3秒後にllama-swap running memberが空へ戻った。
