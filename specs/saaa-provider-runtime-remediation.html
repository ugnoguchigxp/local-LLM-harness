SAAA Provider実機障害の是正と配備後受入

SAAA実機で確認したQwen 3.8 KV:memの再要求timeout、Qwen TTSの公開model拒否、 VOICEVOX PCMとvoice discoveryの不整合を是正する。ソース修正完了と配備後の実機合格は 別の状態として管理し、旧稼働release be5e86272165f4e13e69f4da204b1425486c6070の 結果を新しいソースの合格証跡として扱わない。

Qwen 3.8通常Provider

SAAAはAgent Profile saaa-qwen38、公開model qwen3.8、 route llm-saaa-qwen38を使用する。このrouteはresident runtime qwen-generalだけを候補に持つ。qwen3.8-kv-memは公開catalog、 Profile、利用候補、fallback候補へ含めない。

通常Qwen 3.8のcontextと実行上限
項目 通常推論の契約値
context window 262,144 token
実入力上限 225,280 token
出力予約 32,768 token
安全余白 4,096 token
同時実行数 1 request

225,280は262,144から32,768と4,096を引いた値である。Managed Contextのsource上限、 materialization、永続化方式、容量拡張の保証はこの通常推論契約に含めず、別gateで扱う。

永続KV snapshot経路の廃止

timeoutを起こした専用Providerをroutingから外すだけではなく、snapshot store、slot save／restore、専用 runtimeとrelease、disk quota、systemd書込許可、installerのdirectory作成、conformance scriptを削除する。 Managed Contextはsource-rebuildだけを維持し、source本文を検証してrequestへ挿入する。 詳細契約はManaged Context source rebuild契約に定める。

Qwen TTS公開名

公開名qwen3-tts-expressiveは、upstreamのOpenAI互換routerとoptimized backendの 両方の固定MODEL_MAPPINGで受理し、内部のqwen3-ttsおよび 0.6B-CustomVoiceへ解決する。YAMLのmodel keyだけに依存しない。 配備時は固定upstream revisionへapps/qwen-tts/rocm-gfx1151.patchを適用し、 config.production.yamlを設置してからserviceを起動する。

音声契約

  • GET /v1/audio/voices?model=...は通常Bearer、bodyなしで解決する。
  • WAVはaudio/wavを返す。
  • PCMはaudio/pcm;rate=24000;channels=1;format=s16leを返す。
  • PCM bodyは空でなく、byte数が2の倍数である。
  • X-Audio-Sample-Rate: 24000とX-Audio-Sample-Format: s16leを返す。

2026-09-16実機再検査を受けた追加是正

release 01d0e6f30c114ae8e0c575c3dcefa7f360a412deの再検査では、catalog、JSON Schema、SSE、Qwen TTS内部modelは合格した一方、外部Qwen TTS checkoutへ管理patchが未適用で、 公開aliasとtts-expressive Connectionが失敗した。短文JSONはreasoningだけを返し、 named tool choice objectはbackendで型不一致となった。225,000 token試験は同一GPUの別workerと競合し、 Vulkan device loss後に復旧したため、単独時の合否とは扱わない。

  • prepare-qwen-tts-source.shは固定revision、managed patch、router/backend両aliasを検査し、 installerのall scopeでpatchとproduction configを適用する。preflightでも同じ状態を再検査する。
  • Qwen 3.8の通常要求は明示的reasoning指定がない場合だけenable_thinking: falseを補い、 named tool choiceは対象tool一件とrequiredへ意味保存変換する。
  • 固定semantic probeへのHTTP 400、404、405、422はcontract mismatchとして即時terminal failureにする。
  • 長文canaryは全LARM executionのactive/queuedが15秒連続0であることを送信前条件とし、 300秒以内に成立しなければ長文要求を送らず失敗する。

release e015e5b再検査を受けたfail-closed化

送信前idle観測だけでは実行中のworker侵入を防げず、225,000 token要求は51,200 token地点で vk::DeviceLostErrorとなった。Qwen TTSはwarm時に合格したが、cold voices要求が 同期compile中に切断された。またproduction configを改変してもsource verifierが合格した。

  • 長文canaryは管理token付きX-LARM-Exclusive-Execution: trueを使う。Execution Gateは既存実行をdrainし、排他要求の完了まで全runtimeの新規実行を拒否する。
  • resident Qwenはstrict MTP、ubatch=1024、q8_0/q8_0 KVとし、named tool、厳密literal、 100万文字以上の長文はrequest単位でspeculationを無効化する。厳密literal要求は同値なGBNF制約へ変換する。
  • Qwen TTSはmodel preloadより先にHTTP metadata endpointを公開し、voices取得ではmodel compileを開始しない。lazy preload時のhealthは要求受付可能として扱い、音声生成要求が初回model初期化を行う。
  • 公開HTTP serverのidle timeoutは無効化し、cold activationと長時間推論のdeadlineは Model BrokerとGatewayが管理する。Bun既定の10秒socket timeoutで準備中の接続を切断しない。
  • source verifierは配備済みconfig.production.yamlのbyte一致とmode 0644を必須とし、内容改変・mode改変fixtureを実際のapply/verify経路で拒否する。
