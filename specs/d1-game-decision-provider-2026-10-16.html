d1-3Bゲーム判断Providerの追加と比較モデルの配置

2026-10-16。利用者の承認により、H2O-Lightning-4Bとd1-3Bをrepository外へ配置し、d1-3Bをゲーム判断用のProviderとして追加する。候補比較の方針に基づく。ゲームの入力取得や操作実行、ゲーム専用学習は今回の範囲に含めない。

明示的な選択とライフサイクル

ornith1.5Strix-gameを新しい公開selectorとし、従来のOrnith音声profileの6 Providerにgame-decisionを追加する。game-decisionはdecision.game capability、game-decision-d1経路、d1-system-one runtime、d1-system-one.serviceへ解決する。公開モデルはd1-3b-game、protocolはlarm.system-one.v1。通常のornith1.5StrixとContextStillの選択・Provider構成は維持する。

runtimeはmanagedで、warmの最小数は0。要求時に起動し、idle TTLは120秒。推定メモリ10GB、確保4、同時推論1、待機4、待機期限100msとする。backendは127.0.0.1:8093。Providerの確保・credential・更新・解放は既存のLARM手順を使用する。公開経路を使わない直接同時要求は429で拒否する。

readinessはモデル名によらずdecision.game capabilityに対して既知の移動問題を出し、右方向の回答を検証する。Ruri発話態度用のprobeと混同しない。単純なprobeの成功をゲームの強さの保証としない。

実接続でclaimのcapabilityが既存判断器の固定値になっている問題を検出した。claimは解決済みProviderのcapabilityをschema検証して返すよう修正し、decision.gameの保持と画像転送を確保・claim・Gatewayまで通す回帰試験を追加した。主worktreeの全体checkは修正後も成功した。

テキスト・盤面JSON・画像の入力契約

従来のmodel・state・questionsに、任意のimages配列を追加する。stateは従来の文字列・object・arrayに加え、画像があるときだけnullを許可する。画像はPNG・JPEG・WebPのbase64 data URLに限定し、外部URLを受け取らない。1枚、decode後2MB、元画像1,048,576画素を上限とし、縦横比を保って384×384以内へ縮小する。既存の画像非対応Providerは画像要求を拒否できる。

choice・noul・scoreを扱い、質問は最大16。choiceは名前付き候補または重複のない文字列配列。scoreは2〜10段階。noulのyes確率を変更せず、LARMに必要なconfidenceにmax(p,1−p)を加える。入力tokenは質問を含め最大4096で、画像がある場合は追加1024を予約する。超過は422で拒否し、切り詰めない。

入力と複数質問の共有・確率の読出しは固定された公式実装を使用し、文章を生成して再解釈する処理は追加しない。確率はゲームでの勝率や正解率ではない。状態の版、操作期限、合法手の列挙と、古い結果の破棄は呼び出し側の責務とする。

検証と稼働反映

両モデルの全31ファイルを配置し、byte数とSHA-256がmanifestに一致した。GPU認識、契約検証、通常profileを維持した明示game profileの解決、game readinessの試験、主worktreeのbun run checkが成功した。公開selectorの追加に合わせてOpenAPIの契約試験も更新した。

固定されたupstreamの複数質問用flash attentionは、このROCm版ではCUDAと異なるlog-sum-exp tensor配置となり、複数質問で形状不一致になった。公式実装内の数学的に等価なexplicit GPU tree attentionを選び、解消した。重みとupstreamファイルは変更せず、単一質問のSDPAではgfx1151向けAOTritonの明示opt-inを使用する。choice・noul・scoreの同時回答と画像判断が成功した。

呼び出し時の指定

公開selectorはornith1.5Strix-game、Provider名はgame-decision、modelはd1-3b-game。判断器だけを使う場合はConnection作成時のprovidersにgame-decisionだけを指定する。Ornithも使う場合はllmを加える。旧ConnectionのcredentialはLARM再起動で失効するため、catalogとclaimを再取得する。

  }
