Runtime release stateのcatalog廃止時移行

Runtime IDをrelease catalogから廃止した後も、旧世代が保存した完了済みdeployment recordは /var/lib/larm/runtime-releases.jsonに残り得ます。新世代の起動時は、現行catalogに Runtime IDが存在しない完了済みrecordだけを除去し、現行catalog revisionでatomicに保存し直します。

安全条件

  • 現行catalogにRuntime IDが存在するrecordは、release参照を従来どおり厳格に検証します。
  • 廃止Runtimeにpending operationが残る場合は移行せず、 state_corruptでfail closedします。
  • 完了済みの廃止Runtimeだけを除去し、現行catalogのdefault releaseを通常の初期化処理で追加します。
  • model artifact、provider process、外部credentialはこのstate移行では変更しません。

これはrelease IDの不一致を黙認する互換処理ではありません。同じRuntime IDが現行catalogに残る限り、 unknown release、runtime不一致、未完了operationは引き続き起動失敗になります。
