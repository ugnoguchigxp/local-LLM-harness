検索と削除の仕様

qはtitle・元prompt・利用者タグを対象とし、NFKC・大小文字の正規化、空白区切りAND検索を楽曲と揃える。 日本語の部分一致、タグのAND絞り込み、createdAt/relevance順、asc/descに対応。 limitは既定20・最大100、qは最大512文字、タグは最大32個・各64文字を初期値とする。 cursorに検索条件と安定した日時/IDのキーを含め、異なる検索条件への持ち越しは400。重複・取りこぼしを固定fixtureで検査する。 意味検索や生成モデルの追加ロードは不要な構成にする。

小規模ライブラリ向けに、各完成素材のmetadataを正本として起動時に索引を再構築し、追加・編集・削除時に更新する。 一覧要求のたびに全GLBや全ディレクトリを再読込しない。検索用に新しい外部DBサービスを導入しない。 ID・サイズ・sha256・日時・生成モデル・由来・生成設定・品質注意を保存し、prompt由来のタグを実物の自動認識結果として表示しない。

削除は対象素材のディレクトリを同一filesystem内の削除待ち領域へatomic renameし、一覧から除外してから内容を削除する。 途中で停止しても再起動後に削除を完了し、以後の詳細・GLB・元画像・preview取得は404にする。 実行中jobは完成品削除では操作せず、取消APIを使う。関連する進捗記録からもpromptや入力コピー、成果物URLを除き、削除済みである最小限の記録だけを残す。 元のimage-artifact、他の素材、取得済み生成モデルの重みは連鎖削除しない。3D入力コピーと元画像の別管理をEumenesへ明示する。 すでに開始したdownloadの完了を許す一方、新しい取得は拒否する契約とする。

生成workerとLARMの調停

  1. Profileが広告する3D serviceでmodel・対応入力を発見し、生成要求を受理・永続化する。素材の検索などでは会話Providerを不必要に起動しない。
  2. prompt入力なら既存Qwen Imageを先に確保して画像を生成・保存し、画像workerの停止を待って確保を解放する。3D枠を保持したまま画像枠を待たない。
  3. 3Dの実行枠・資源を確保し、loopbackの専用adapterをsystemdで起動する。adapterは固定CLIを引数配列で実行し、入力・workをjob専用にする。
  4. alphaがあることだけで切り抜き済みと判断せず、必要に応じてBiRefNetを明示する。shape・texture・postprocessを実行し、認識できる段階だけを進捗へ反映する。
  5. GLB parse、geometry、UV、PBR画像、サイズ・hashを検査し、品質注意をmetadataへ保存する。モデル生成成立と色・編集向け品質を区別する。
  6. 成果物を永続化し、worker停止・資源解放を確認してcompletedを公開する。停止失敗時はworker_stop_failedとし、検証済みデータを非公開の回復対象として保護する。 このデータは通常の失敗work掃除で消さず、容量予約を維持して停止確認後に保存済み結果から復旧できるようにする。自動再生成しない。

初版のadapterはtrellis-cliをjobごとの子プロセスとして管理する方針とする。 trellis-serverの素の/health・mutexだけでは永続job、進捗、中断、待機上限を提供できないため、既存の画像Providerと同じ管理境界を設ける。 readinessでは実行物・モデルmanifestと保存先を検査し、推論を健康確認のために実行しない。 新規unitの仮名はlarm-mesh-trellis2.service、自動起動なし、Restart=no、常駐数0・完了後idle TTL 0。 パッケージやドライバの更新は前提にせず、試験済み配布物とモデルhashを固定する。

画像・楽曲・3Dを同じ重量級生成グループに入れ、同時実行は全体で1件。 MediaVariantManagerの2択、waitingMusic固有の待機処理、runtime-variant.shのother指定、systemd Conflicts、限定polkit権限、媒体設定・起動検査を3種類に対応させる。 他の要求が使用中のworkerを切替処理で強制停止しない。待機順と期限を定義し、既存音楽の待機動作を回帰試験する。 初期案は3D待機4件・開始待ち10分・実行30分。モデル未起動の待機と実行を分ける。

メモリは初期予約32 GiB＋既存の16 GiB余白を保守的な開始値とし、byte換算を既存会計と統一する。 実測RSS約1.46 GiBだけへ縮めない。共有GTT、host複製、冷えたcache、複雑な入力を考慮し、実行中もMemAvailableを監視する。 取消・期限切れ・メモリfloor割れでは対象jobの子プロセス群だけを止め、停止確認後にcancelled/failedへ遷移する。 画像・楽曲間の排他だけでLLMとの資源調停が済んだとはせず、実際のProfile→route→runtimeの割当・予約・優先度を確認して新しい3D実行を待機させる。 観測中のLLM名から利用者の意図を推定して停止・置換しない。

Eumenesスキルへ渡す連携契約

Profileのservice広告へname mesh、capability media.mesh.generate、protocol larm.mesh-generation.v1、 endpoint /v1/3d/generations、model trellis2-4bを追加する案とする。 audienceに沿ったControl URLを使い、Eumenesへ内部worker portやホスト保存パスを指定させない。 既存の画像・音楽serviceやProfileの要求Provider subsetを保ったまま広告・SDK・OpenAPIを拡張する。

  1. 生成依頼では入力画像IDかprompt、title/tagsを渡し、1つの意図につき再送キーを固定する。
  2. jobIdを保存して状態またはSSEを追跡する。Eumenes側の通信timeoutを生成失敗と取り違えず、同じjobを確認する。
  3. 完了時はassetId、モデルURL、preview URLと品質注意を表示する。再表示は保存済み素材を取得し、再生成しない。
  4. 「前に作ったロボット」等はq/tagsで検索して候補を示す。削除は利用者の明示依頼と確定したassetIdへ行う。
  5. HTMLはEumenes backendの認証付き取得・中継、またはGLB取得後のBlob表示を使う。LARMのBearerをHTMLやURL queryへ埋め込まない。

viewerは固定した表示コードを使い、title/prompt等をHTMLとして実行させない。 単体previewをiframeへ載せる場合は表示用に隔離し、生成APIを操作する秘密情報を持たせない。 初版のGLBは試験済みWebP/PBRを踏襲し、対応viewer条件をdescriptionへ記載する。 Eumenes側へ渡す成果物は、API一覧、要求/応答例、状態遷移、検索・削除・再送手順、エラー対応、HTML表示方法をまとめた連携仕様とする。 Eumenes実装やスキルファイルの変更は、本計画の作成作業には含めない。

受入試験

  • 画像ID入力とprompt入力の両方で、1つの生成意図が1つのjob・素材になり、再送・timeout・再起動で重複生成しない。
  • completedは検証・保存・worker停止の後に公開され、取得・検索・preview・削除ではworkerが起動しない。
  • 実際の画像・楽曲・3Dの保存デバイスが一致し、3D workもディスク上に置かれる。保存先不在・満杯・権限不足時に別場所へ逃げない。
  • 日本語・英語・正規化・複数語・タグ・並び順・cursor不正・ページ間削除を含む検索試験を通す。
  • 取消と完成品削除が区別され、途中停止からの削除完了、入力コピーとpreviewの回収、削除後の全URLの404、他の素材・元画像・重みの保護を確認する。
  • 不正ID・パス逸脱・symlink・過大入力・壊れたGLB・未対応解像度・資格情報不正を拒否し、公開metadata/HTMLへホストパスや秘密を含めない。
  • 画像・音楽・3Dが同時にGPU生成しない。会話の実割当と資源調停が保たれ、元の音楽待機・画像停止契約を回帰試験する。
  • 色・トポロジーの警告は成功の事実と併記する。境界辺0だけを編集・3D印刷向け品質の合格とはしない。
  • 実装後に関連固定試験、typecheck、deployment・docs検査、最後にbun run checkを完了する。実生成は合意した一連操作で確認し、無条件の自動再送をしない。

本計画の完了条件は、API・保存場所・ライフサイクル・Eumenes接続と実装順序をレビューできる状態にすること。 現時点で新APIの利用可能・本番反映済みとは報告しない。
