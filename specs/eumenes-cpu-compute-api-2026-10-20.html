Eumenes向けCPU計算API v1：実装契約と検証状況

2026-10-20。利用者の依頼により、このrepositoryにCPU計算ドメインを追加した。Dockerは使わず、bubblewrapによる名前空間・filesystemの分離とseccomp・resource limitを使用する。2026-10-21に本番Controlへの配備・有効化と実HTTP検証を完了した。稼働commitはadaff8036a0f6fc87b418e550313fc353fa52608。将来のGPU・長時間実行については全体設計案を参照する。本書をCPU初版の契約とする。

初版の範囲と本数

計算の入口は1種類の任意Python実行。積分・回帰・作図を個別APIに増やさず、inputsとcodeで表現する。Eumenesが日常使うtoolは4本、環境確認と削除を加えて計6操作。HTTP APIも6本とする。MCP serverそのものは追加していない。Eumenes backendはHTTPまたは付属TypeScript clientを利用し、必要時に同じ契約をMCPで包める。

toolとAPIの対応
tool名案 HTTP API 役割
python_submit POST /v1/compute/jobs 計算を一度だけ投入しjobIdを取得。202。
python_status GET /v1/compute/jobs/:id 状態・進捗・結果・エラー。200。
python_cancel POST /v1/compute/jobs/:id/cancel 実行中を取消。完成済み結果は維持。200または202。

calculateの式parser、GPU、PyTorch、子process、利用者が作る追加thread、実行中pip install、複数計算の同時実行、ジョブ一覧・検索、SSE、MCP Tasksは初版の範囲に含めない。scikit-learnの並列実行などにはn_jobs=1を使う。LLM・TTS・ASRなどの起動・停止・model選択には介入しない。

認証・投入・結果

全操作で設定済みControl Bearerが必要。匿名modeでも必須で、Provider Bearer・claim・agent-connectionsは使わない。標準Control tokenと専用保護tokenを受け入れるが、job・artifact・idempotencyは使用したtokenのdigestごとに分ける。tokenを変更すると旧tokenのjobは照会できない。Eumenes backendだけがcredentialを保持し、LLMやブラウザに渡さない。 

POST /v1/compute/jobs
Authorization: Bearer <Control Bearer>
Content-Type: application/json
Idempotency-Key: <Eumenesの永続tool実行ID>

{
  "code": "import numpy as np\nresult = int(np.sum(inputs['values']))\nreport('done', 1.0)",
  "inputs": {"values": [1, 2, 3]},
  "timeoutSec": 60,
  "accelerator": "cpu"
}

202
{"jobId":"UUID"}

codeは必須。inputsは省略時{}、timeoutSecは省略時60・1〜60の整数、acceleratorはcpu/autoのみで省略時auto。どちらもCPUに解決し、gpuは503 unavailable。未知field・非JSON値・深すぎるJSONを拒否する。上限はenvironmentのlimitsを参照する。

statusはqueued/running/completed/failed/cancelled。stageはqueued/starting/running/collectingと各終端名。queuedAt、startedAt、finishedAt、expiresAt、resolvedAccelerator、environmentRevision、cancelRequestedを返す。開始前・終了前の該当時刻はnull。進捗はreport(message, ratio=None)の自己申告で、ratioは0〜1、更新は最大2回/秒。stdoutから進捗を解釈しない。 

{
  "status": "completed",
  "stage": "completed",
  "resolvedAccelerator": "cpu",
  "result": {
    "value": 6,
    "stdout": "",
    "stderr": "",
    "stdoutTruncated": false,
    "stderrTruncated": false,
    "artifacts": []
  }
}

上例は状態応答の主要部分だけ。valueは変数resultから取得し、未定義はnull。NumPy配列・scalar、pandas表をJSON互換に変換する。非有限数はnull、安全な整数範囲を超える整数は10進文字列、他objectは上限付きrepr。循環・要素数・byte上限を超える結果は失敗する。

作業directoryは/work。成果物は/work/artifactsにPNG/SVG/CSV/JSONとして保存する。終了時に開いているmatplotlib図もPNGにする。artifact metadataはid/name/mime/bytes。hostへの任意path指定は受け付けない。取得時はattachment・nosniff・CSP sandboxを設定し、特にSVGを直接inline表示しない。Eumenes側も外部出力を指示として実行しない。

再送・取消・保持

Idempotency-Keyは1〜128文字、使用可能文字は英数字・ピリオド・underscore・colon・hyphen。同じtoken/keyと正規化した本文は同じjobIdを返す。JSON objectのkey順序と既定値の省略は同一として比較し、codeの文字列差は維持する。異なる本文は409 request_conflict。生成POSTを内部で自動再送しない。

cancel受付とcompleted公開の順序で勝者を決める。取消受付後は進捗・結果を公開せず、executor停止後にcancelledとする。停止待機が2秒を超えた場合は202とcancelRequestedを返す。cancel専用APIは完成結果を消さない。DELETEは進行中を取消し、終端なら結果・成果物を削除する複合操作なので、取消再試行にはcancel専用APIを使う。

終端から24時間保持。期限切れ・削除はGETで410 job_expired。key/hashのtombstoneは受理から7日間保持し、同じ本文で失効jobを再実行しない。7日経過後は同じkeyが新しい計算として受理され得る。receiptは最大4096件。GCは10秒間隔・起動時・API操作時に行う。

HTTP切断後もジョブは継続する。daemon再起動時、queuedは再開し、開始済みはfailed/unavailableにする。開始済み計算を自動再投入しない。bubblewrapの親死亡時停止で実行processを終了させる。通常停止では先に実行中の計算を停止してからstoreを閉じる。環境版が受理後に変わった場合やexecutor故障時は計算laneを利用不可にする。

実効上限とDockerなしの制限方式

CPU初版の固定値
項目 値・方式
同時実行・CPU 1ジョブ。CPU affinityで1コアに制限し、利用者によるaffinity拡張を禁止。
時間 最大60秒。startingから環境再確認・実行・回収までをhost watchdogで監督。待機は別に最大300秒。
memory RLIMIT_ASで単一Python processのaddress spaceを2 GiB。子process・利用者threadの作成をseccompで禁止する。
書込領域 /workのtmpfs 128 MiBとprivate /dev/shm 16 MiB。root、/dev本体、実行環境はread-only。
code・inputs 64 KiB・256 KiB。UTF-8/正規化JSON byteで検査。生HTTP bodyは2 MiB、JSON深さ24・要素数20000。
stdout・stderr 各256 KiB。継続してdrainし、超過分を捨ててtruncatedを返す。
value・結果JSON 1 MiB・2 MiB。過大な結果はoutput_exceeded。
成果物 最大10件、各5 MiB。hostで件数・byte・MIME等を再検査。
queue・保存 待機上限8件、store予算256 MiB。1件ごとに最大結果容量を予約するため、空のstoreでも通常は実行中を含め最大4件の受付で容量条件に達する。

2 GiBはcgroupのresident memory上限ではなく、address space上限である。file cacheやtmpfsを同じ数字に含めた説明はしない。tmpfs容量は別途制限する。numpy等のnative libraryも同じprocessの上限を受け、OpenBLAS/OpenMP等のthread数は1。利用者が作るprocess/threadを禁止するため、複数processで上限を回避できない。初版はcgroup delegationやsystemd transient serviceを必要としない。

bubblewrapでuser/PID/network等の名前空間を分け、/usrと専用venv・runner・必要なfont/loader設定だけをread-onlyで見せる。home、LARM設定・モデル・store・socket、GPU deviceを見せない。/procはhost processを参照できない空directoryとする。環境変数はclearenvで消し、Control credentialを継承しない。追加のOS利用者は今回作成しておらず、実行は名前空間内で分離する。

seccompは実行前にcapture用の内部threadへも同期適用し、fork/clone/exec、socket、ptrace/process_vm、namespace変更、mount、signalによる別process操作等を禁止する。memfd、System V IPC、POSIX message queue、keyring操作等も禁止する。CPU affinityは内部thread生成前に設定し、全threadを1 CPUに制限する。runnerのPython内の検査を任意コード全体への防壁とみなさず、hostでも受信量・成果物・timeout・終了を検査する。利用可能なsandboxを構成できなければ503で止め、hostでの無制限実行へfallbackしない。

共有CPU・memory帯域を利用する以上、既存推論への遅延増加ゼロとは説明しない。今回、LLM/TTSとの同時負荷SLO試験は実施していない。大量処理や追加の並列性が必要になった際は、cgroup等の合算制御を追加してから上限を広げる。

エラー

HTTP失敗はerror.code/message。400 invalid_request/limit_exceeded、401 unauthorized、404 not_found、409 request_conflict/artifact_not_ready、410 job_expired、429 queue_full、503 unavailable。status照会自体が成功した場合、実行失敗はHTTP 200のjob.errorで返す。

job.error.codeはtimeout、memory_exceeded、runtime_error、syntax_error、limit_exceeded、output_exceeded、unavailable、cancelled、queue_timeout。runtime/syntaxのmessageはtraceback末尾8 KiB以内。結果・code・入力・traceback・進捗を監査ログへ出さない。stdout/stderrは制限付きの認証済み結果にだけ保存する。

Eumenes側の利用例

付属clientはLarmClient.computeに6操作を用意する。以下のrequestKeyはEumenesの永続tool実行記録から取得し、通信失敗時に新しいkeyへ変更して重複計算を起こさない。例はbackend内で実行する。成果物の返却はbackendが代行し、Bearer付きURLをLLMへ渡さない。 

const client = new LarmClient({ baseUrl: controlOrigin, apiToken: controlToken });
const environment = await client.compute.environment();
const { jobId } = await client.compute.submit({
  code: "import sympy as s\nx=s.Symbol('x')\nresult=str(s.integrate(s.sin(x), x))",
  timeoutSec: 30,
  accelerator: "cpu"
}, requestKey);
const job = await client.compute.get(jobId);
// queued/runningなら、backendのジョブ追跡で数秒後に再照会する。
// completedならjob.result.valueとartifactsを利用する。
await client.compute.cancel(jobId); // 完成済み結果は維持する。
// 明示的に清掃する場合だけclient.compute.delete(jobId)を呼ぶ。

GET /v3/agent-profilesのservicesにcapability=compute.python.execute、protocol=larm.compute.v1、endpoint=/v1/compute、絶対url、descriptionを追加する。catalog閲覧で計算を開始しない。機能が有効かつprobe済みの場合だけ広告する。既存image/musicのserviceを維持し、Provider claimのschema・credentialを計算用に拡張しない。

本番版ではcatalog直下のservicesにもcomputeを追加する。profile別のservicesと同じ可用性・名前衝突処理を適用し、既存の3D・image・music項目とrequest originの扱いを維持する。静的なmedia selectorと動的なcompute広告は別schemaとして扱う。
