試験結果

  • Core／Backend／Daemon API／Clientを含む全app／package試験432件が成功した。
  • deployment test 29件と全shell deployment testを含むbun run checkが成功した。
  • strict schema、deterministic selection、required budget、tokenizer mismatch、lifecycle epoch fenceを検証した。
  • Source token数はlive canonical tokenizerによるsidecar attestationと登録値を照合し、自己申告だけでは 20M境界を通過できない。実Chat promptもtemplate適用後に再計数し、過少申告を422で拒否した。
  • sourceはprincipal別opaque handle、SHA-256、UTF-8、size、symlink／inode再検証でfail closedした。512 GiB source quota、256 GiB free floor、process間provision lockもwrite前に検証した。
  • materializationはExecutionGate取得とrelease再検証の後にだけ行い、Active Viewは一回でconsumeした。
  • runtime policyはSource Set 20,000,000 token、Active View上限225,280 tokenを固定した。
  • 別port／一時stateのlive daemonでresidentをACTIVE、cold quality workerを STANDBYと観測し、両方の公開modeがsource-rebuildだけであることを確認した。
  • 再監査後のlive resident Chatでattested sourceからone-shot Viewをconsumeした。Active Viewは910 token、template適用後promptは1,083 token、GatewayはHTTP 200、operationは source_rebuild_materializedで成功し、ContextとAllocationをreleaseした。
  • live metricでactivation、active runtime、operation、materialization時間、prefill token、cache miss、 source-only cache byteを確認した。

tokenizer digestは固定した多言語5入力に対する/tokenize応答のcanonical SHA-256であり、bun run context:source:conformanceで再測定できる。 source本文、credential、生成本文は証跡へ保存していない。KV snapshot試験は別証跡であり、 productionのverified modeを自動では拡張しない。
